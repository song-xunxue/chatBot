## 1. 引言

定义客户端 ↔ 服务端、面板 ↔ 服务端、插件 ↔ 核心 的全部接口契约。所有接口基于 `02-技术架构` 的双通道（WebSocket 主通道 + REST 管理通道）。

## 2. 通信总览

| 通道 | 端点（示例） | 方向 | 用途 |
|---|---|---|---|
| WebSocket | `wss://<host>/ws?token=<access_token>` | 双向 | 实时消息、流式回复、状态推送、桌宠抖动 |
| REST | `https://<host>/api/...` | 请求-响应 | 人设/插件/模型/历史/代人聊天/文件上传 |

- 鉴权：单人场景，统一一个 `ACCESS_TOKEN`（存 `.env`）。WS 经 query 参数、REST 经 `Authorization: Bearer <token>`。
- 内容类型：REST 用 `application/json`；文件上传 `multipart/form-data`。
- 时间戳：统一 Unix 毫秒（`ts`）。

## 3. WebSocket 主通道协议

### 3.1 消息信封

所有 WS 帧均为如下 JSON：

```json
{
  "type": "<事件类型>",
  "object_id": "<聊天对象ID，管理类事件可省略>",
  "msg_id": "<消息ID，仅消息类事件>",
  "payload": { },
  "ts": 1730000000000
}
```

### 3.2 入站事件（客户端 → 服务端）

| type | payload | 说明 |
|---|---|---|
| `user_msg` | `{text?: str, attachments?: [{kind: "image"\|"audio"\|"sticker", ref: str}]}` | 用户发送消息；多模态用 attachments |
| `presence` | `{status: "online"\|"typing"\|"away"}` | 在线/输入中状态 |
| `recall` | `{msg_id}` | 撤回用户自己已发消息（F-C-10 撤回） |
| `delete` | `{msg_id, reason?: "out_of_character"}` | 删除消息；`out_of_character` 触发人格负反馈（F-C-10 删除） |
| `sync_req` | `{since_ts}` | 请求该时间点之后的增量消息（重连同步） |

### 3.3 出站事件（服务端 → 客户端）

| type | payload | 说明 |
|---|---|---|
| `ai_start` | `{msg_id}` | 一条 AI 回复开始（流式） |
| `ai_chunk` | `{msg_id, delta: {text?\|audio?\|image?\|sticker?}}` | 流式增量分片 |
| `ai_done` | `{msg_id, state: {mood, status, energy}}` | 回复结束 + 最新状态 |
| `state_update` | `{mood, status, energy, ts}` | 主动状态变更（动态心情插件） |
| `nudge` | `{object_id}` | 通知客户端触发桌宠抖动（F-C-11） |
| `sync_resp` | `{messages: [...]}` | 增量同步返回 |
| `proactive_msg` | `{text, ...}` | 聊天对象**自主发消息**（时间观念/自主发消息插件） |
| `error` | `{code, message}` | 错误 |

### 3.4 流式回复时序

```
client: user_msg           → server
server: ai_start           → client
server: ai_chunk (×N)      → client   // LLM token 边产边推
server: ai_done            → client   // 含插件阶段产物(语音/图/表情包)
```

## 4. REST 管理通道 API

> 路径前缀 `/api`；响应统一信封：`{code, message, data}`。

### 4.1 人设管理（F-S-02）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/persona` | 列出所有人设 |
| POST | `/persona` | 新建人设（body: 人设 JSON） |
| GET | `/persona/{id}` | 获取单个 |
| PUT | `/persona/{id}` | 更新 |
| DELETE | `/persona/{id}` | 删除 |
| POST | `/persona/import` | 导入人设 JSON 文件（兼容 `persona_*.json` 结构） |
| POST | `/persona/{id}/avatar` | 上传头像/人设图片（multipart） |
| GET | `/persona/{id}/export` | 导出为 JSON |

### 4.2 插件管理（F-S-04）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/plugin` | 已安装插件清单 + 全局开关状态 |
| POST | `/plugin/{name}/enable` \(`/disable`) | 全局一键开关 |
| GET | `/plugin/object/{object_id}` | 该聊天对象启用的插件 |
| PUT | `/plugin/object/{object_id}` | 为该对象配置插件集 + 各插件参数 |

### 4.3 LLM 模型配置（F-C-03）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/model/providers` | 支持 provider 列表（glm/deepseek/siliconflow/lmarena） |
| PUT | `/model/providers` | 配置各 provider 的 API Key/端点（写 `.env` 持久化，不回显 Key） |
| PUT | `/persona/{id}/model` | 为人设绑定 provider + 模型名 + 参数 |

### 4.4 聊天记录（F-C-04）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/history?object_id=&limit=&cursor=` | 分页查询（游标分页） |
| DELETE | `/history?object_id=&before_ts=` | 清理早于阈值的记录（对应"保存上限"） |

### 4.5 代人聊天（F-S-03）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/proxy/toggle` | `{object_id, enabled}` 一键开关大模型；关后用户代答 |
| POST | `/proxy/reply` | `{object_id, text}` 提交用户代答内容（入库 + 用于反推人格） |

### 4.6 文件/资源

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/upload/sticker` | 上传表情包（JPG）（F-C-08） |
| POST | `/upload/background` | 上传聊天背景（F-C-11） |
| GET | `/static/{path}` | 静态资源（头像/表情包/背景） |

## 5. 人设 JSON Schema

兼容 `persona_雷姆.json` 现有结构（`data.prompts.<id>.data.{name,description,personality,scenario,creator_notes,avatar_path}`），并扩展**语言、图片、动态状态、特殊回复**字段。

```jsonc
{
  "schema_version": "1.0",
  "data": {
    "prompts": {
      "<uuid>": {
        "data": {
          "name": "雷姆",
          "language": "zh-CN",                       // 新增：人设语言
          "description": "背景/自我介绍长文本",         // 对应原 description
          "personality": "性格长文本",                 // 对应原 personality
          "scenario": "场景长文本",                    // 对应原 scenario
          "creator_notes": "核心人设指令",             // 对应原 creator_notes
          "avatar": "static/avatar/<id>.jpg",         // 头像（服务端路径）
          "images": ["static/persona/<id>/1.jpg"],    // 新增：人设参考图（用户上传）
          "dynamic_state": {                          // 新增：动态人性化属性
            "mood": "温柔",
            "status": "在宅邸整理家务",
            "energy": 0.8
          },
          "special_replies": [                        // 新增：特殊回复规则
            { "when": {"keyword": "早安"}, "reply": "...", "weight": 1.0 }
          ],
          "model": {                                  // 新增：绑定模型
            "provider": "glm", "model": "glm-4.6", "params": {}
          },
          "plugins": ["mood_dynamic", "tts", "image_gen"] // 新增：启用插件
        }
      }
    }
  }
}
```

> 导入旧 `persona_*.json` 时，缺失字段以默认值填充，并向用户提示补全。

## 6. 插件 API（钩子契约）

插件实现以下钩子（按需，详见 `05-插件系统设计`）。钩子均为 `async`，接收/返回 `MessageContext`：

| 钩子 | 触发点 | 典型用途 |
|---|---|---|
| `on_message_in(ctx)` | 收到用户消息后、LLM 前 | 多模态预处理、敏感词、联网搜索注入 |
| `on_before_llm(ctx)` | 拼 prompt 后、调用 LLM 前 | 改写 prompt、注入记忆摘要 |
| `on_after_llm(ctx)` | LLM 产出后 | TTS、图像生成、表情包生成（F-P-01/02/03） |
| `on_message_out(ctx)` | 回复发往客户端前 | 回复增强、多条合并（F-P-05） |
| `on_tick(ctx)` | 定时（cron-like） | 动态心情、时间观念、自主发消息（F-S-04） |
| `on_delete(ctx)` | 消息被标记删除 | 人格负反馈学习（F-C-10） |

## 7. MCP / 工具接口

聊天对象可声明可用的 MCP 工具（联网搜索、图像生成、知识检索等）。LLM 通过 function calling 调用，结果回灌上下文。工具调用走服务端统一的 `tool_call` 抽象，具体 MCP server 配置在 `.env`/配置文件。

## 8. 错误码

| code | 含义 |
|---|---|
| 0 | 成功 |
| 1001 | 未授权 / token 无效 |
| 1002 | 参数校验失败 |
| 2001 | LLM 调用失败 |
| 2002 | LLM 限流/超配额 |
| 2003 | 插件异常 |
| 3001 | 资源不存在（人设/对象） |
| 3002 | 文件上传失败 |
| 4001 | 今日图像生成已达上限（F-P-02 自主拒绝） |
| 5000 | 内部错误 |
