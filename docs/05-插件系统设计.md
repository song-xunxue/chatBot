## 1. 引言

定义本项目插件（plugin）系统的架构、生命周期、钩子契约、隔离策略与按聊天对象配置机制，覆盖 F-S-04（插件工程化）与 F-P-01~05（五类需求插件）。

## 2. 设计目标

- **工程化、模版化**：新增插件不改核心，照模版即可写（F-S-04）。
- **多插件不冲突**：钩子优先级 + 异常隔离 + 资源协调（F-S-04）。
- **一键开关**：全局开关 + 按聊天对象启用（F-S-04）。
- **人性化**：内置动态心情、时间观念、自主发消息等插件（F-S-04）。
- **借鉴 AstrBot**：参考其 star 装饰器注册、事件总线、插件配置思路，但本项目自研轻量化实现。

## 3. 总体架构

```
        ┌──────────────── PluginManager ────────────────┐
        │  load/enable/disable/reload  +  manifest 索引  │
        └───────────────────┬───────────────────────────┘
                            │ 注册钩子
        ┌───────────────────▼───────────────────────────┐
        │              EventBus（事件总线）              │
        │   on_message_in / on_before_llm / on_after_llm│
        │   on_message_out / on_tick / on_delete        │
        └───────────────────┬───────────────────────────┘
                            │ 按优先级分发
   ┌──────────┬─────────────┼──────────────┬────────────┐
 plugin_TTS  plugin_Img  plugin_Mood  ...
```

- `PluginManager`：扫描插件目录、加载 manifest、实例化、注册钩子、管理开关与按对象配置。
- `EventBus`：管道各阶段触发对应事件，按优先级调用订阅插件，支持中断。
- 插件间不直接调用，只通过 `MessageContext` 与事件交互。

## 4. 插件清单（manifest）

每个插件目录含 `plugin.yaml`：

```yaml
name: tts                 # 唯一名（kebab-case）
version: 0.1.0
author: 李文煜
description: 语音合成插件（F-P-01）
entry: plugin.py          # 入口模块（定义 Plugin 子类）
hooks:                     # 声明订阅的钩子 + 优先级（小先执行）
  - { name: on_after_llm, priority: 100 }
default_enabled: false
config_schema:             # 插件可配置项（驱动面板表单）
  voice: { type: string, default: "female-soft" }
  speed: { type: number, default: 1.0 }
requires:                  # 能力依赖
  modality: [audio_out]
```

## 5. 插件基类与生命周期

```python
class Plugin(ABC):
    manifest: PluginManifest
    async def on_load(self, ctx: PluginContext) -> None: ...   # 加载：读配置、连资源
    async def on_unload(self) -> None: ...                      # 卸载：释放资源
    # 业务钩子在子类按需实现（见 §6）
```

生命周期：`discover → load → enable → (hook 调用) → disable → unload`。reload 支持（改配置后热加载）。

## 6. 钩子 / 事件系统

钩子签名统一为 `async def hook(ctx: MessageContext) -> HookResult`，`HookResult` 可为 `CONTINUE` / `STOP`（中断后续插件与管道）。

| 事件 | 触发点 | 中断影响 |
|---|---|---|
| `on_message_in` | 用户消息入库后 | 中断则丢弃该消息 |
| `on_before_llm` | prompt 拼装后、调 LLM 前 | 中断则不调 LLM（如直接由插件产出回复） |
| `on_after_llm` | LLM 真实产出后（LLM 被跳过时不触发） | STOP 跳过 on_message_out（回复增强） |
| `on_message_out` | 回复发出前（置于 stage_save 前，改写入历史） | 中断后续同钩子插件；流式下 token 已发送，无法撤回 |

> **流式语义注**：回复 token 在 LLM 流式阶段已逐个推送客户端（ai_chunk）。`on_after_llm`/`on_message_out` 对 `ctx.reply_text` 的改写体现在最终的 ai_done 全量文本与历史落库（on_message_out 置于 stage_save 之前），但无法逐 token 增量下发。富内容（TTS/图像/表情包）写入 `ctx.rich`，由 WS 层在 ai_done 携带（M4.3 落地）。
| `on_tick` | 定时（cron-like，每插件配周期） | —（驱动自主发消息/心情/时间观念） |
| `on_delete` | 消息被标记删除 | —（驱动人格负反馈） |

分发按 `priority` 升序；单个插件抛异常被 EventBus 捕获、记录、跳过，不影响其他插件与主流程（异常隔离，§8）。

## 7. 上下文与依赖注入

`MessageContext` 贯穿一次消息处理，字段含：`object_id`、`user_msg`、`attachments`、`prompt`（可改）、`llm_response`（可改）、`reply`（最终）、`state`、`memories`、`services`（注入的 Redis/LLM/资源访问器）。插件通过修改 ctx 影响管道，无需互相感知。

## 8. 隔离与冲突避免

| 机制 | 说明 |
|---|---|
| 异常隔离 | 每个钩子调用 `try/except`，异常记录后跳过该插件 |
| 优先级 | `priority` 决定执行序，敏感阶段（改 reply）按约定排序 |
| 资源协调 | 同时产语音/图像/表情包时，由 `on_after_llm` 内统一收集到 `reply.rich` 列表，按类型合并而非覆盖 |
| 配置隔离 | 插件配置按 `object_id` 命名空间存储，互不串扰 |
| 并发 | 同一对象串行处理消息（1对1场景无并发），避免竞态 |

## 9. 全局开关 + 按聊天对象配置

- 全局：`mychat:plugin:{name}:enabled`（总闸，对应 REST `/plugin/{name}/enable`）。
- 按对象：`mychat:plugin_cfg:{object_id}:{name}` = JSON（启用位 + 参数，对应 REST `/plugin/object/{object_id}`）。
- 解析：插件钩子触发时，Manager 注入「该对象是否启用此插件 + 该对象的参数」；未启用则跳过。

## 10. 五类需求插件设计

| 插件 | 钩子 | 要点 |
|---|---|---|
| **tts**（F-P-01） | `on_after_llm` | 把回复文本合成语音，加入 `reply.rich.audio`；voice 可克隆（参考 clonetts） |
| **image_gen**（F-P-02） | `on_after_llm` | 基于人设参考图 + LLM 提示/智能体/MCP 生成图；**日上限**：每次 `INCR mychat:quota:{oid}:img:{date}`，超阈值→`ctx.reply.text` 改为「自主拒绝」并 `STOP` 图像生成分支 |
| **sticker_gen**（F-P-03） | `on_after_llm` | 生成表情包 JPG，落 `sticker/` 并可加入 `reply.rich.sticker` |
| ~~lmarena~~（F-P-04，已移除） | — | 2026-06-19 用户决定不做 lmarena |
| **reply_enhance**（F-P-05） | `on_before_llm`/`on_message_out` | 输入累积：`on_message_in` 累计连续用户输入，按规则（停顿/条数/语义完整性）判断「攒够再回」；输出合并：多段回复合并为一条 |

> **M4.3 实现注**：四类插件落 `server/app/plugins/`（tts/image_gen/sticker_gen/reply_enhance）；多模态经 `server/app/modality/` 的 TTS/Image Provider 抽象接入（默认 stub，真实 provider 待 Q-10 确认后经 `register_tts/register_image` 注册）。image_gen 日配额键 `mychat:quota:{oid}:img:{date}`，超额改回复为「自主拒绝」并 STOP 图像分支；reply_enhance 输入累积默认关闭（`accumulate=false`），开启后达 `flush_count` 或末条句末标点即合并 flush，否则 on_before_llm STOP 暂缓（WS 发 `held` 指示）。

## 11. 人性化插件（F-S-04 内置）

| 插件 | 钩子 | 行为 |
|---|---|---|
| **mood_dynamic**（动态心情） | `on_tick`/`on_after_llm` | 依对话/时间更新 `state.mood`，回灌 prompt（参考 angel_heart） |
| **time_aware**（时间观念） | `on_tick` | 感知早晚/季节，生成问候/状态（参考 life_scheduler/daily_sharing） |
| **proactive_msg**（自主发消息） | `on_tick` | 按策略（定时/事件/概率）触发 `proactive_msg` 推送 + `nudge` 桌宠抖动（参考 daily_sharing/what_to_eat） |
| **persona_evolve**（人格反推） | `on_delete`/代人聊天入库 | 删除=out_of_character 作负样本，代人回答作正样本，调用人设自设定流程（参考 self_evolution） |

> **M4.4 实现注**：四插件落 `server/app/plugins/`（mood_dynamic/time_aware/proactive_msg/persona_evolve），由 `TickScheduler` 周期触发 `on_tick`、`ConnectionRegistry` 支撑主动推送。mood_dynamic 用关键词情感启发式(零依赖)更新心情值并注入 prompt、on_tick 向中性衰减；time_aware 注入时辰/季节并缓存标签；proactive_msg 按概率+冷却广播 `proactive_msg` 信封(含 nudge 桌宠抖动)；persona_evolve 经 on_delete 直接累积删除负样本(与 M3 记忆侧 `record_negative_feedback` 并行、各司其职)，达阈值仅产出"进化提案"(待 M7 面板人工确认，**不自动改写人设**以避免漂移)。

## 12. 插件开发模版

提供 `server/app/plugins/_template/`：

```
_template/
├── plugin.yaml        # manifest 模版
├── plugin.py          # class TemplatePlugin(Plugin) + 钩子示例
└── README.md          # 编写说明
```

新增插件：复制模版 → 改 manifest + 实现钩子 → 放入 `plugins/` → 面板自动发现。
