## 1. 概述

V1.0（M0–M8）已上线 `43.140.219.99:8000`，master 分支。V1.1 在 `dev/v1.1` 分支开发，针对用户测试反馈的 5 类问题：人设字段过简、代人聊天缺失、反推人设、插件中文化、客户端简化美化。

V1.1 规划由 workflow 编排产出：6 子系统并行设计 → 对抗审查（6 个 verdict 均 `needs-rework`，挖出多个 V1.0 既有 bug）→ 综合成 M9–M14 六里程碑。

## 4. M9 人设卡片扩字段 + REST 合并语义修复

**目标**：PersonaCard 加四组嵌套可选字段；renderer 分段渲染（非空才输出，旧卡逐字节不变）；importer/exporter 双向兼容嵌套/扁平；**修复 V1.0 PUT 全量替换丢字段 + created_ts 重置 bug**（改 PATCH 深度合并）。

**改动**：
- `persona/models.py`：新增 `Profile`(age/gender/occupation/appearance/race/speech_style/catchphrase，均 `str=''`)、`Preferences`(likes/dislikes `list[str]`)、`Relationship`(relation/greeting)、`DialogueExample`(user/character)；PersonaCard 加 `profile`/`preferences`/`relationship`/`example_dialogue`/`version`(int=1)/`history`(list)；`from_dict` 扩展嵌套构造 + 容忍 history/version 未知键；age 统一 `str`。
- `persona/renderer.py`：新增【人物画像】【喜好与厌恶】【与用户的关系】【开场白】【示例对话】段，全"非空才输出"；段顺序固定；`greeting` 只在【开场白】渲染一次；`MAX_DIALOGUE_RENDER=5`、`MAX_LINE_CHARS=200` 截断。
- `persona/importer.py`：`_extract_profile/_preferences/_relationship/_ialogue` 兼容嵌套/扁平两形态；旧 JSON 不报错。
- `persona/store.py`：`export_persona` 补新字段入 data 顶层 + prompts.data；新增 `snapshot_persona`(单调递增 version_no)/`rollback_persona`。
- `api/rest_persona.py`：`update_persona` 改 **PATCH 深度合并**（get→body 覆盖→嵌套深度合并→set），保留 created_ts。

**接口**：`GET/POST /persona`、`GET/PUT/DELETE /persona/{id}` 签名不变（PUT 语义改 PATCH 合并）；新增 `GET /persona/{id}/history`、`POST /persona/{id}/rollback`。

**测试**：m3 `test_persona_renderer`（全空==V1.0 黄金串、profile 渲染、greeting 单段、dialogue 截断）、`test_persona_importer`（嵌套/扁平往返）、`test_persona_store`（嵌套往返、export→import 幂等）、`test_rest_persona`（**PUT 不再清空 model/avatar/dynamic_state、created_ts 保留、深度合并**）。

**风险**：PUT 丢字段是 V1.0 既有 bug，扩到 25+ 字段后爆炸半径剧增 → 必须改 PATCH。

## 6. M11 代人聊天 A：面板模拟训练

**目标**：面板 Roleplay 工作台——选对象 → 录 user+assistant 对话 → 入库正样本，列表可增/改/删；**正样本物理隔离到独立键**（绝不污染 LLM 上下文）。本里程碑只产数据，不实现反推。

**改动**：
- `chat_store.py`：新增独立键 `_roleplay_key`/`_roleplay_neg_key`；`list_roleplay`/`append_roleplay_pair`/`update_roleplay`/`delete_roleplay`(删时写入 neg 队列)/`clear_roleplay`；mid 用 uuid4；**不改** `append_message`/`get_history`（V1.0 零侵入）；软上限 1000。
- `rest_admin.py`（或新 `rest_roleplay.py`）：`POST/GET/PUT/DELETE /api/v1/roleplay/{oid}/messages`、`GET /api/v1/roleplay/{oid}/live`（读代人开关，A 只读）；object_id 校验（已绑定人设才允许）。
- `Roleplay.vue`：升级为"工作台 + 提案（折叠）"双区；对象下拉、对话编辑表（user/assistant 增删改）、入库、触发反推（M12 未就绪 disable）、live 状态提示。

**Redis 键**：`mychat:chat_roleplay:{oid}`（正样本 List）、`mychat:roleplay:neg:{oid}`（负样本 List）。

**测试**：m7 `test_roleplay_training`（录/改/删）、**`test_roleplay_isolation`（关键：正样本不进 `mychat:chat:{oid}`，get_history 取不到）**、`test_object_id_validation`。

**风险（头号）**：若复用 `mychat:chat:{oid}` 会污染 LLM 上下文（`get_history` 不过滤 source）→ 必须物理隔离。

## 7. M12 反推人设·直接合并

**目标**：实现 D3。采集正样本（A 面板 + B 实时代答，统一 `mychat:reverse_infer:pos:{pid}`）+ 负样本（统一 `mychat:reverse_infer:neg:{pid}`，废弃旧双路径）；LLM 提炼 → 字段白名单 + 幅度上限 → **两步契约**（dry_run→diff+token→apply）→ 合并前快照入 history → 一键回滚。persona_evolve 改仅采集。

**改动**：
- `persona/reverse_infer.py`（新）：`infer_and_merge(redis, persona_id, mode='fill_empty', dry_run=True)`；`FIELD_WHITELIST`（name/id/avatar/model/plugins/dynamic_state 永不触碰）；drift 度量 = 字符级 edit distance / max(旧值长度,1)；`MAX_FIELDS_TOUCHED=6`（整体接受/拒绝，不按字符截断拆散语义）；LLM temperature=0、JSON raw_decode 容错、无 key 降级空 diff。
- **两步落库契约**：`POST /persona/{id}/reverse-infer`（强制 dry_run）→ diff + `confirm_token`（绑定内容）；`POST /persona/{id}/reverse-infer/apply{token}`→ 凭 token 落库（防改参）；落库前 snapshot。
- 样本归属统一：采集点写 `pos/neg:{pid}`（采集时经 `get_object_persona_id` 解析 oid→pid）；废弃 `persona_evolve:samples` 与 `memory:pending` 双路径混用；persona_evolve 插件保留 on_delete 采集但写新键、移除提案分支。
- `store.py`：`PersonaCard.history`(list，max=20，元素存精简平铺快照不嵌套历史防写放大)；`snapshot_persona`(单调递增 version_no)、`rollback_persona`(回滚前先 snapshot 保证可再回滚)；并发保护：`version` + CAS 冲突 409 或 per-pid asyncio.Lock。
- `rest_persona.py`：新增 reverse-infer 两端点 + `samples`/`history`/`rollback`；处置旧 `/persona_evolve/proposals`（deprecated/删除）+ Roleplay.vue 提案区迁移。

**测试**：m7 `test_reverse_infer`（白名单过滤、fill_empty/overwrite、幅度、整体接受、dry_run 不落库、apply 后 history+1、rollback 可再回滚、LLM 失败降级、JSON 鲁棒、空样本不调 LLM、temp=0 幂等）、`test_reverse_infer_pid_attribution`（跨 oid 归属）、`test_concurrent_merge_cas`(409)。

**风险**：persona_id↔object_id 键空间错配（采集时写 pid）；history 嵌套写放大（精简快照）；并发丢更新（CAS）。

## 8. M13 代人聊天 B：实时接管

**目标**：实现 D1-B。per-object 代人开关，客户端 user_msg 旁路 LLM → 推代答请求到面板 → 人工代答经 REST 回推客户端。承接 M12（代答为正样本采集点）。**代答进四级完整记忆**（D6）。

**改动**：
- `shared/protocol.py`：新增 `TYPE_TAKEOVER_REQUEST/RESOLVED/TIMEOUT/PENDING/SUBSCRIBE` + 便捷构造。
- `takeover/` 子包（service/panel_bus）：`is_takeover_enabled`/`set_takeover_enabled`(Redis `mychat:takeover:enabled:{oid}` 持久)；`open_takeover_request`(pending_id 用 Redis INCR 序列防碰撞、per-object 单 active pending)；`resolve_takeover_answer`；panel_bus 内存 set[WebSocket] 隔离广播、启动检测 enabled 键广播 resync。
- `ws.py`：`_handle_user_msg` 开头代检 → 命中 `_handle_takeover_bypass`（append user 严格 1 条防双写、HSET pending、发 ai_start + `TYPE_TAKEOVER_PENDING`、广播 request 到 panel_bus、不调 run_stream）；**bypass 仍触发 `stage_memory_write`**（D6 代答进记忆）；elif 链显式加 `TYPE_TAKEOVER_SUBSCRIBE` 路由；pending TTL 到期服务端主动发 `TYPE_TAKEOVER_TIMEOUT`。
- `rest_takeover.py`：`POST /takeover/toggle`、`GET /takeover/status`、`GET /takeover/pending`、`POST /takeover/answer`(resolve+broadcast ai_done source=takeover 到客户端 + resolved 到面板 + append assistant + 采集正样本 M12 + DEL pending + 审计日志)；pending 失效 410；断线恢复 = 代答落库 + 重连 GET /history 整段按 ts 去重（**不依赖 V1.0 未实现的 sync_resp**）。
- 客户端 `main_window.py`：`_on_msg` 加 `TYPE_TAKEOVER_PENDING`(渲染"等待人工代答…")/`TIMEOUT` 分支；ai_done(source=takeover) 可选标灰；超时由服务端驱动非客户端自计时。

**测试**：m7 `test_takeover_service_toggle`、`test_takeover_bypass_skips_llm`(run_stream 0 次 + user 严格 1 条)、`test_takeover_pending_dedupe_ordering`、`test_takeover_answer_broadcasts_source_takeover`、`test_takeover_answer_missing_returns_410`、`test_takeover_server_timeout_sent`、`test_takeover_panel_subscribe_routed`、`test_takeover_resync_on_restart`、`test_takeover_offline_recovery`、`test_takeover_memory_behavior`(D6 锁定)。

**风险**：sync_resp V1.0 未实现（改整段历史去重）；pending 同 tick 碰撞（INCR 序列）；客户端 120s 空白气泡（服务端主动发 PENDING）；panel_bus 重启丢订阅（resync）。

## 9. M14 客户端微信式简化美化（D5）

**目标**：客户端重构为**微信式两端**——左聊天对象列表 + 右聊天区，去掉人设管理/设置入口，无对象提示去面板添加，温馨长方形窗口；桌宠去闲置弹跳、仅回复时抖动。

**改动**：
- `main_window.py`：重构为 `QSplitter` 左右两端。**左侧对象列表**（`QListWidget`，从 `list_personas` 拉人设作为聊天对象，item 带 persona_id；点击切换当前 object_id → WS 切换 + Store 切换）；**右侧聊天区**（ChatView）；**去掉**人设抽屉 CRUD、⚙设置按钮、顶栏 mood 占位；顶栏极简（对象名 + 在线圆点）；**空状态**（无对象时右侧显示"暂无聊天对象，请到管理面板添加"）；窗口尺寸长方形（如 960×640）。
- `theme.py`：温馨调色板强化（珊瑚粉/暖橙/米白已有），对象列表项选中态/hover、圆角、分隔线。
- `chat_view.py`：保留多模态按钮(📎/🎙/😀)；去掉背景设置入口（背景固定温馨色或由服务端配）。
- `pet_window.py`：删 `_start_idle`/`_idle` 闲置弹跳；`shake()` 加防叠加；仅 `ai_done`/`proactive_msg` 触发。
- `main.py`：窗口尺寸 + 桌宠行为 docstring 更新。

**接口**：复用 `GET /persona`（对象列表）；切换对象走 WS object_id（客户端本地切换，无需新端点）；如需服务端记录"当前对象"复用 `POST /persona/{id}/bind/{object_id}`。

**测试**：`test_pet_shake_only`(ai_done 后 shake、无 _idle)、`test_pet_shake_dedupe`、`test_object_list_switch`(点击切换 object_id、WS/Store 切换)、`test_empty_state`(无对象提示)、回归 `test_ui_smoke`/`test_m6`。

**风险**：微信式是较大重构（原单列+抽屉 → 两端），需保证 WS/Store 接线在对象切换时正确；温馨风格需实测视觉效果。

## 10. 跨里程碑设计约定

- **并发**：`PersonaCard.version` + CAS（M9 加字段，M12 合并时启用），冲突 409；或 per-pid asyncio.Lock 串行化 snapshot/merge/set。
- **样本归属**：统一用 persona_id 键（`reverse_infer:pos/neg:{pid}`），采集点经 `get_object_persona_id` 解析。
- **REST 人设**：PUT 改 PATCH 深度合并（M9），所有写人设处（面板编辑/反推合并）走同语义。
- **代答记忆**：bypass 仍触发 `stage_memory_write`（D6）。
- **Redis 键新增汇总**：`mychat:chat_roleplay:{oid}`、`mychat:roleplay:neg:{oid}`、`mychat:reverse_infer:pos/neg:{pid}`、`mychat:takeover:enabled/pending/audit:{oid}`、PersonaCard 内 `history`/`version` 字段。
