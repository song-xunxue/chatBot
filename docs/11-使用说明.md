## 3. 管理面板功能用法（V1.1）

### 3.1 人设管理（Persona 页）
- 创建/编辑人设：**分组表单**——基本信息 / 人物画像(年龄·性别·职业·外貌·种族·说话风格·口头禅) / 与用户关系(关系·开场白) / 对话样本(示例对话) / 喜好厌恶。**所有字段缺省可空**。
- 编辑保存为 **PATCH 深度合并**（局部编辑不清空其他字段）。
- 支持 JSON 导入/导出、头像上传、模型绑定、绑定到聊天对象。

### 3.2 插件管理（Plugin 页）
- 插件按**分类分组**展示（开发与模板 / 对话处理 / 富媒体生成 / 人性化 / 人设与进化），中文名 + 功能说明。
- 全局开关（NSwitch）+ 按对象配置（为不同聊天对象开不同插件）。

### 3.3 记忆管理（Memory 页）
- 查看四级记忆统计 + 长期/情节/核心记忆表，手动遗忘单条。

### 3.4 代人聊天 A — 面板模拟训练（Roleplay 页）⭐ V1.1 新功能
**用途**：人工录入"用户说什么 + 角色该回什么"示范对话，用作反推人设的正样本。

1. 进入「代人聊天」页 → 「模拟训练工作台」
2. 选择聊天对象（需已在人设页绑定）
3. 在两个文本框分别填 **用户消息** 和 **角色回复** → 点「录入这对对话」
4. 已录对话列表可**改 / 删**（删除会记为负样本）
5. 积累若干对后，点「触发反推」→ 进入反推预览（见 3.5）

> 这些对话**物理隔离**存储，不会污染正常聊天的 LLM 上下文。

### 3.5 反推人设 — 直接合并（两步预览）⭐ V1.1 新功能
**用途**：从代人对话（正样本）+ 删除的不符人格回复（负样本），用 LLM 提炼人设字段，合并进人设卡。

1. 在代人聊天页点「触发反推」→ 服务端调 LLM 提炼
2. **预览 diff**：展示每个字段的「旧值 → 新值」（只填空字段模式 fill_empty，或覆盖模式 overwrite）
3. 确认无误 → 点「应用」合并落库（合并前自动快照入 history，支持回滚）
4. 人设页可查看历史快照、一键回滚

> 安全：字段白名单（name/id/avatar 等核心字段永不被改）+ drift 幅度上限 + 合并前快照可回滚。

### 3.6 代人聊天 B — 实时接管 ⭐ V1.1 新功能
**用途**：开启后，该对象的客户端消息**不走 LLM**，转由你在面板手动代答。

1. 面板调 `POST /api/v1/takeover/toggle {object_id, enabled:true}` 开启某人代入模式
2. 客户端发消息 → 服务端旁路 LLM → 推「代答请求」到面板待答列表 + 客户端显示「⏳ 等待人工代答…」
3. 面板代答（`POST /api/v1/takeover/answer`）→ 回推客户端 + 入库 + **进四级记忆**（D6）
4. 超时（120s）服务端主动发超时提示

> 代答默认符合人设，不符合的会进入反推负样本调整人设。

## 4. 部署流程（本地 → 云服务器）

> 仅在改了服务端代码后需要重新部署。客户端改动无需部署。

### 4.1 本地打包（排除隐私/构建产物）
```bash

# 先构建最新前端（dashboard 改动后）

# 打包（排除 __pycache__/node_modules/src/Ref/client/.pem/.git，只含 dashboard/dist）
tar czf /tmp/chatbot.tar.gz \
  --exclude='__pycache__' --exclude='*/node_modules' --exclude='dashboard/src' \
  --exclude='Ref' --exclude='client' --exclude='*.pem' --exclude='.git' \
  server shared dashboard/dist dashboard/index.html docker-compose.yml scripts .env
```

### 4.2 上传 + 远端部署
```bash
# SSH 密钥 .claude/ubuntu.pem（已 chmod 600，已 gitignore）
SCP_KEY=D:/code/Git_Local/ChatBot/.claude/ubuntu.pem
scp -i $SCP_KEY -o StrictHostKeyChecking=no /tmp/chatbot.tar.gz ubuntu@43.140.219.99:~/
ssh -i $SCP_KEY -o StrictHostKeyChecking=no ubuntu@43.140.219.99 \
  "rm -rf ~/StandardProject/ChatBot && mkdir -p ~/StandardProject/ChatBot && \
   tar xzf ~/chatbot.tar.gz -C ~/StandardProject/ChatBot && \
   cd ~/StandardProject/ChatBot && sudo bash scripts/deploy.sh"
```

- `deploy.sh`：docker compose build + up + health 检查

- 两个容器：`mychat-redis` + `mychat-server`

## 8. 常见问题

**Q: GitHub 推送失败 `7890 refused`？**
A: 梯子（代理 127.0.0.1:7890）没开。开梯子后 `git push github dev/v1.1`。Gitee 国内直连不需代理（若代理干扰，`git -c http.proxy="" push origin ...`）。

**Q: 客户端连不上服务端？**
A: 检查 `CLIENT_SERVER_URL`/`CLIENT_WS_URL`/`ACCESS_TOKEN` 环境变量或 `run_cloud.bat`；确认服务端 `/health` 可达；腾讯云安全组放行 8000/tcp。

**Q: 代人聊天 B 开启后客户端一直转圈？**
A: 正常——客户端显示「⏳ 等待人工代答…」，需在面板 `/takeover/pending` 待答列表手动代答。120s 未代答会超时。

**Q: 反推没提取出字段？**
A: 需先在代人聊天 A 录入正样本（无正样本会 aborted）；且需配置 GLM key（反推用 glm provider）；diff 为空可能是字段已有值（fill_empty 模式不覆盖，换 overwrite）。

**Q: 如何回滚反推合并？**
A: 人设页 `GET /persona/{id}/history` 看快照版本，`POST /persona/{id}/rollback {version_no}` 回滚。
