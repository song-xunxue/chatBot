## 1. 引言

本文档定义 MyChat 项目的总体技术架构、分层与模块划分、技术选型、通信与部署方案。是 `03-接口设计`、`04-数据模型`、`05-插件系统`、`06-记忆系统` 的共同上游。

## 2. 总体架构

### 2.1 架构概览

```
┌─────────────────────────────┐         ┌──────────────────────────────────────────┐
│      客户端 (Win11)          │         │           服务端 (Ubuntu22.04 云主机)      │
│  PySide6 桌面应用 + 桌宠      │         │                                          │
│                             │  WS/REST │  FastAPI (ASGI/uvicorn)                  │
│  ┌───────────┐ ┌─────────┐  │ ◄─────► │  ┌────────────────────────────────────┐  │
│  │ 主聊天界面 │ │ 桌宠窗口 │  │         │  │ 消息处理管道 Pipeline              │  │
│  └───────────┘ └─────────┘  │         │  │  ├─ 多模态理解(图/语音)            │  │
│  ┌─────────────────────────┐│         │  │  ├─ 记忆系统(长短期+遗忘)         │  │
│  │ 本地持久化 SQLite+文件   ││         │  │  ├─ 人设注入                      │  │
│  └─────────────────────────┘│         │  │  ├─ 插件链(钩子)                 │  │
│  ┌─────────────────────────┐│         │  │  └─ LLM Provider(GLM/Ds/硅基/lm) │  │
│  │ 网络通信层 WS Client     ││         │  └────────────────────────────────────┘  │
│  └─────────────────────────┘│         │  Redis (Docker)  │  Vue3 面板(独立工程)   │
└─────────────────────────────┘         └──────────────────┴──────────────────────┘
```

### 2.2 分层职责

| 层 | 客户端 | 服务端 |
|---|---|---|
| 表现层 | PySide6 主窗口/桌宠/输入面板 | Vue3 Web 管理面板 |
| 应用层 | 会话编排、消息收发调度 | 消息处理管道、代人聊天、事件分发 |
| 领域层 | （薄，逻辑下沉服务端） | 人设、记忆、插件、LLM、多模态理解 |
| 数据层 | SQLite + 本地资源文件 | Redis + 人设/插件文件 |
| 通信层 | WebSocket Client + REST Client | FastAPI WebSocket + REST |

**原则**：核心智能逻辑（人设、记忆、LLM、插件、多模态理解）一律在**服务端**，客户端仅做「展示 + 采集 + 本地缓存」，对应 F-C-09「后端在云服务器，前端仅展示」。

## 3. 技术选型

| 维度 | 选型 | 说明 / 理由 |
|---|---|---|
| 客户端 GUI | **PySide6** | Qt 官方 LGPL；透明置顶无边框窗口、系统托盘、动画成熟；Python 全栈一致；PyInstaller 打包 |
| 服务端框架 | **FastAPI** | 原生 async；WebSocket 一等公民；自动 OpenAPI；契合流式 LLM 响应 |
| ASGI 服务器 | uvicorn（生产 gunicorn+uvicorn worker） | FastAPI 标配 |
| Web 面板 | **Vue3 + Vite + TS** | 独立工程，参考 AstrBot；UI 库候选 Naive UI / Element Plus（待定） |
| 实时通信 | WebSocket（主）+ REST（管理） | 双向实时消息 + 配置/历史 CRUD |
| 云端存储 | **Redis**（via Docker） | 聊天记录/记忆/状态/缓存 |
| 本地存储 | **SQLite** + 文件 | 结构化记录缓存；表情包/背景/人设图片资源 |
| LLM Provider | 自研统一抽象 | GLM(智谱) / DeepSeek / 硅基流动 / lmarena |
| 多模态理解 | 图像走多模态 LLM / 视觉模型；语音走 ASR | 具体服务在接口设计/计划阶段定 |
| 部署 | Docker Compose | Redis + server 一键；进程 `restart: always` |
| Python 版本 | 3.11（服务端/客户端一致） | Ubuntu 22.04 自带 Python 3.10；统一用 Docker 镜像（`python:3.11-slim`）跑 3.11，不动系统 Python |

> 说明：PySide6 与 PyQt6 API 几乎等价，选 PySide6 因其 LGPL 授权更宽松（Qt 官方维护）。

### 4.2 消息处理管道（Pipeline）

一条用户消息进入服务端后的处理顺序（每阶段可被插件钩子拦截/增强）：

```
[入站消息] →①多模态理解(图/语音→文本/描述)
          →②人设注入(拼装 system prompt + 动态状态/心情)
          →③记忆检索(基于人设+消息召回相关长期记忆)
          →④插件 on_before_llm 钩子
          →⑤LLM 调用(流式)
          →⑥插件 on_after_llm 钩子(语音/图像/表情包生成)
          →⑦回复增强(多条合并/输入累积判断)
          →⑧记忆写入 + 状态/心情更新
          →[出站回复]（WebSocket 推回客户端）
```

- 管道用 `MessageContext` 对象贯穿，各阶段读写共享上下文。
- 流式：LLM 阶段 token 流式产出，边产边通过 WebSocket 推送，降低首字延迟。

### 4.3 LLM Provider 抽象

统一接口，屏蔽各家差异：

```python
class LLMProvider(ABC):
    name: str
    async def chat(self, messages: list[Message], **opts) -> Message: ...
    async def stream_chat(self, messages: list[Message], **opts) -> AsyncIterator[Delta]: ...
    def supports(self, modality: Modality) -> bool: ...   # text/vision/audio
```

- `registry` 按聊天对象配置的 provider 名实例化对应实现。
- 硅基流动 / lmarena 为聚合型，内部再路由到具体模型。

### 5.1 桌宠实现要点（F-C-11）

- 透明无边框置顶：`Qt.FramelessWindowHint | Qt.WindowStaysOnTopHint` + `setAttribute(Qt.WA_TranslucentBackground)`。
- 白色浮动圆圈：`QWidget` + `paintEvent` 用 `QPainter` 绘制圆 + `QPropertyAnimation` 做呼吸/漂浮动效。
- 抖动：收到消息时对窗口 `pos` 属性做上下 `QPropertyAnimation`（限定次数）。
- 交互：点击 → 显示主聊天窗口、隐藏桌宠；主窗口最小化 → 显示桌宠。

## 6. 通信设计

### 6.1 双通道

| 通道 | 协议 | 用途 |
|---|---|---|
| 主通道 | WebSocket | 实时双向：用户消息、AI 回复（含流式）、状态/心情推送、桌宠抖动触发、在线状态 |
| 管理通道 | REST | 人设/插件/模型配置、历史查询、代人聊天开关、文件上传 |

### 6.2 WebSocket 消息信封

```json
{ "type": "<事件类型>", "object_id": "<聊天对象ID>", "payload": { }, "ts": 0 }
```

事件类型：`user_msg` / `ai_chunk` / `ai_done` / `presence` / `state_update` / `sync_req` / `sync_resp` / `error`。（细节见 `03-接口设计`）

### 6.3 离线与重连

- 客户端断线本地缓存消息，重连后按 `ts` 水位增量同步。
- 服务端为离线期间的消息保留待推队列。

## 7. 部署架构

### 7.1 Docker Compose（服务端）

```yaml
services:
  redis:    { image: redis:7-alpine, restart: always, /* 启用 ACL/密码 */ }
  server:   { build: ./server, restart: always, env_file: .env, depends_on: [redis] }
  # 可选 nginx: 反代 + 面板静态资源 + HTTPS
```

### 7.2 Ubuntu 22.04 部署要点

- 系统 Python 3.10；本项目统一用 Docker 镜像（`python:3.11-slim`）跑 3.11，不动系统 Python。
- Docker 安装：`apt` 装 `docker.io` + `docker-compose-plugin`（或官方源），无需处理老旧 glibc 问题。
- 防火墙（`ufw`）放行面板端口；Redis 仅容器内网通信，不直接暴露公网。
- 原 CentOS7 因 2024-06-30 EOL 已弃用（用户 2026-06-15 重装为 Ubuntu 22.04）。

### 7.3 进程守护

- 容器 `restart: always` 保证 7×24（NFR-A-01）。
- 日志统一输出，便于排障。

## 9. 关键技术风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 服务器资源有限（2核4G） | 高负载卡顿 | LLM/TTS/图像均走远程 API、本地轻量；监控内存 |
| LLM API 不稳定/限流 | 回复失败 | 重试 + 多 Provider 降级 + 友好提示 |
| 桌宠透明窗口跨版本差异 | 显示异常 | PySide6 在 Win11 已验证成熟，预留降级（系统托盘） |
| 记忆/人设反推效果不可控 | 人格漂移 | 提供「代人聊天 + 删除负反馈」人工回路校准 |
| 流式 WebSocket 与管道集成复杂 | 开发量 | 管道阶段异步生成器统一产出 Delta |
| 面板与核心并行开发量大 | 进度 | 面板可后置（已与用户确认独立工程，按里程碑排期） |
