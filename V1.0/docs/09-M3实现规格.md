## 0. 顶层约束（不可违背）

1. 人设/记忆/协调器**全部服务端常驻**，客户端仅展示（F-C-09、SAD §2.2）。
2. 管道顺序锁定：`load_history → persona_inject → memory_retrieve → llm_stream → save → memory_write`，人设先于记忆检索（SAD §10 v0.3）。
3. 流式不变：persona/memory 全部在第一个 token yield 前就绪；memory_write 在流结束后异步触发（`asyncio.create_task`），失败不阻塞回复。
4. 向后兼容：`MessageContext` 新字段一律带默认值，`memory_coordinator is None` 或 `settings.memory_enabled=False` 时自动降级到 M2 行为。
5. Redis Key 全局前缀 `mychat:`，时间戳一律 Unix 毫秒（`ts`），以 04 文档为准修正 06 的简写。
6. 首版检索零新依赖：纯关键词召回 top-K（Redis Hash 全量取出 + 内存关键词匹配），预留 embedding 接口（`Retriever` 抽象）。

## 2. 四级记忆数据结构

### 2.1 层级定义（已确认四级）

| 层 | 名称 | 内容 | 生命周期 | Redis 结构 | 键 |
|---|---|---|---|---|---|
| Core | 核心记忆 | 人设静态部分 + 用户核心画像（姓名/关键关系/绝对偏好） | 常驻，手动维护 | String(JSON) | `mychat:mem:{object_id}:core` |
| Working | 工作记忆 | 最近 N 轮原文 | 滑动窗口 | List | 复用 `mychat:chat:{object_id}`（即 chat_store） |
| Episodic | 情景记忆 | 对话摘要 + 反思 | TTL + 活跃度衰减 | Sorted Set(score=ts) + List(反思) | `mychat:mem:{object_id}:episodic` / `mychat:mem:{object_id}:reflect` |
| Long-term | 长期记忆 | 事实/偏好/关系/事件 | 持久 + 遗忘评分 | Hash(field=mid) | `mychat:mem:{object_id}:long` |

> 决策依据：06 文档原本三级(Working/Short/Long)，已确认决策 1 把"Short-term 摘要+反思"合并命名为 **Episodic**，并新增 **Core** 常驻层承载"人设静态+用户核心画像"。这对应 06 §8 prompt 注入结构里的 `[system]`(人设) 与 `[state]` 部分需要常驻、不滑出。Core 层与 Long-term 区别：Core 全量注入每次对话（人设框架），Long-term 按相关性 top-K 召回。


```python
from dataclasses import dataclass, field, asdict
from enum import Enum
import time

class Layer(str, Enum):
    CORE = "core"
    WORKING = "working"
    EPISODIC = "episodic"
    LONG_TERM = "long_term"

class Category(str, Enum):
    FACT = "fact"
    PREFERENCE = "preference"
    RELATIONSHIP = "relationship"
    EVENT = "event"
    PERSONALITY = "personality"

@dataclass
class MemoryItem:
    """长期记忆条目（06 §3 完整字段，补齐 04 缺失的 category/emotion）"""
    id: str                              # mid, uuid4
    content: str                         # 记忆文本
    category: Category = Category.FACT
    importance: float = 0.5              # 0~1, 写入时 LLM 评定
    emotion: float = 0.0                 # 0~1, 情感强度，影响衰减
    created_ts: int = 0                  # Unix 毫秒
    last_access_ts: int = 0
    access_count: int = 0
    forgotten: bool = False              # 软遗忘标记，可恢复
    source: str = "dialog"               # dialog/import/proxy/extract
    def __post_init__(self):
        if not self.created_ts:
            self.created_ts = int(time.time() * 1000)
        if not self.last_access_ts:
            self.last_access_ts = self.created_ts

@dataclass
class EpisodicEntry:
    """情景记忆摘要条目（ZSet member JSON）"""
    id: str
    summary: str                         # LLM 摘要
    span_start_ts: int
    span_end_ts: int
    created_ts: int = 0
    turn_range: tuple[int, int] = (0, 0) # 覆盖的 turn_index 范围
    def __post_init__(self):
        if not self.created_ts:
            self.created_ts = int(time.time() * 1000)

@dataclass
class CoreFact:
    """核心记忆条目（常驻注入）"""
    key: str                             # 如 "user_name" / "persona_trait:温柔"
    content: str
    locked: bool = False                 # 锁定防遗忘

@dataclass
class RecallResult:
    """coordinator.retrieve 返回"""
    core: list[CoreFact] = field(default_factory=list)
    working: list = field(default_factory=list)       # list[Message]
    episodic: list[EpisodicEntry] = field(default_factory=list)
    long_term: list[MemoryItem] = field(default_factory=list)
    hit_mids: list[str] = field(default_factory=list) # 被召回的 long_term mid，供更新访问统计

@dataclass
class ForgetConfig:
    w_importance: float = 0.4
    w_recency: float = 0.3
    w_access: float = 0.15
    w_emotion: float = 0.15
    retain_threshold: float = 0.3       # 跌破则 forgotten=True
    decay_half_life_hours: float = 72.0 # recency_decay 半衰期
    cleanup_interval_turns: int = 50    # 物理清理周期
```

### 2.4 遗忘评分（`memory/forgetting.py`）

```python
import math, time

def recency_decay(last_access_ts: int, now_ts: int, half_life_hours: float) -> float:
    """间隔重复衰减：exp 形式，每次被召回重置 last_access_ts 即重置衰减"""
    elapsed_hours = max(0.0, (now_ts - last_access_ts) / 3_600_000.0)
    return math.exp(-0.693 * elapsed_hours / half_life_hours)  # ln2/half_life

def retain_score(item: MemoryItem, cfg: ForgetConfig, now_ts: int | None = None) -> float:
    now_ts = now_ts or int(time.time() * 1000)
    return (
        cfg.w_importance * item.importance
        + cfg.w_recency * recency_decay(item.last_access_ts, now_ts, cfg.decay_half_life_hours)
        + cfg.w_access * math.log1p(item.access_count)
        + cfg.w_emotion * item.emotion
    )

def should_forget(item: MemoryItem, cfg: ForgetConfig, now_ts: int | None = None) -> bool:
    if item.forgotten:
        return True
    return retain_score(item, cfg, now_ts) < cfg.retain_threshold
```

> 权重初值取 06 §10 建议 `0.4/0.3/0.15/0.15`，全部走 `settings` 可配置。

### 3.2 导入兼容（`persona/importer.py`）

兼容两种形态（见样例分析）：
- **嵌套形态**（persona_雷姆.json / persona_林挽夏.json）：`data.prompts.<任意key>.data.{name,description,personality,scenario,creator_notes,avatar_path}`
- **扁平形态**（ST V2 完整卡）：`data.{name,description,...}`

```python
def parse_persona_json(raw: dict, persona_id: str = "") -> PersonaCard:
    data = raw.get("data", raw)
    # 优先取嵌套 prompts.<key>.data
    inner = {}
    prompts = data.get("prompts")
    if isinstance(prompts, dict) and prompts:
        first_key = next(iter(prompts))
        inner = prompts[first_key].get("data", {}) or {}
        pid = persona_id or first_key
    else:
        inner = data  # 扁平形态
        pid = persona_id or ""
    card = PersonaCard(
        id=pid or f"persona_{int(time.time()*1000)}",
        name=inner.get("name", ""),
        description=inner.get("description", ""),
        personality=inner.get("personality", ""),
        scenario=inner.get("scenario", ""),
        creator_notes=inner.get("creator_notes", ""),
    )
    # avatar_path 剥离路径只留文件名，标记需重新上传
    ap = inner.get("avatar_path", "")
    if ap:
        card.avatar = f"static/avatar/{card.id}/{os.path.basename(ap)}"
    return card
```

兼容规则（落实样例建议）：
1. 用 `.get(key, "")` 兜底每个字段，personality/scenario 允许空。
2. `prompts` 多 key 取首个，不硬编码 key 名（容忍空格/撇号）。
3. `avatar_path` 跨设备不可移植，剥离路径只留文件名，落 `static/avatar/{id}/`。
4. `encoding='utf-8'` 读文件。
5. 缺失 language/images/dynamic_state 等新字段用默认值填充。

## 4. MemoryCoordinator 完整工作流（`memory/coordinator.py`）

服务端常驻单例（仿 `get_redis()` 模式），对外四个入口：

### 4.1 retrieve（检索，每轮对话同步调用，token 前完成）

```python
class MemoryCoordinator:
    def __init__(self, redis, llm_provider=None, cfg: ForgetConfig = ForgetConfig()):
        self.redis = redis
        self.llm = llm_provider
        self.cfg = cfg
        self.retriever = KeywordRetriever()  # 首版关键词，预留 EmbeddingRetriever

    async def retrieve(self, object_id: str, query: str, top_k: int = 5,
                       working_messages: list | None = None) -> RecallResult:
        # 1. Core 常驻全量注入
        core = await store.get_core(self.redis, object_id)
        # 2. Working（复用传入的 working_messages，避免重复读 Redis）
        working = working_messages or []
        # 3. Episodic 最近 N 条摘要
        episodic = await store.get_episodic(self.redis, object_id, limit=3)
        # 4. Long-term 关键词召回 top-K（retriever 内部 HGETALL 全量 + 内存关键词匹配 + 评分排序）
        long_all = await store.get_all_long_term(self.redis, object_id)  # forgotten=False
        long_hits, hit_mids = self.retriever.retrieve(long_all, query, top_k)
        # 5. 召回即访问：更新 last_access_ts / access_count（间隔重复）
        await store.touch_long_term(self.redis, object_id, hit_mids)
        return RecallResult(core=core, working=working, episodic=episodic,
                            long_term=long_hits, hit_mids=hit_mids)
```

### 4.2 render（组装 prompt 文本，对应 06 §8 注入结构）

```python
    def render(self, result: RecallResult) -> str:
        """生成 memory_block 文本，注入位置：人设之后、工作记忆之前"""
        blocks = []
        if result.long_term:
            facts = "\n".join(f"- {m.content}" for m in result.long_term)
            blocks.append(f"【相关长期记忆】\n{facts}")
        if result.episodic:
            sums = "\n".join(f"- {e.summary}" for e in result.episodic)
            blocks.append(f"【近期对话摘要】\n{sums}")
        return "\n\n".join(blocks)
```

> Core 不进 memory_block——它已并入 persona system_prompt 的【核心人设指令】段（人设静态部分即 Core 的子集）。用户核心画像若需独立常驻，作为 CoreFact 单独渲染到 system_prompt 尾部。

### 4.3 on_turn_complete（编码 + 遗忘，流结束后异步触发）

```python
    async def on_turn_complete(self, ctx) -> None:
        """在 stage_save 之后由 stage_memory_write 调用（asyncio.create_task 包装）"""
        try:
            # 1. Working 已由 stage_save 写入 chat_store，此处只做溢出判定
            turn_count = await store.get_turn_count(self.redis, ctx.object_id)
            # 2. 溢出 → 触发 Episodic 摘要（LLM 总结最近 K 轮为摘要条目）
            if turn_count > 0 and turn_count % settings.memory_episodic_summarize_threshold == 0:
                recent = await store.get_working_span(self.redis, ctx.object_id,
                                                      settings.memory_episodic_summarize_threshold)
                summary = await self.encoder.summarize(recent, self.llm)
                await store.append_episodic(self.redis, ctx.object_id, summary, ...)
            # 3. 反思：每 N 次摘要触发一次
            if store.count_episodic(self.redis, ctx.object_id) % settings.memory_episodic_reflect_interval == 0:
                reflection = await self.encoder.reflect(await store.get_episodic(...), self.llm)
                await store.append_reflection(self.redis, ctx.object_id, reflection)
            # 4. Long-term 事实抽取（LLM 评分 importance/emotion/category）
            facts = await self.encoder.extract_facts(ctx.user_text, ctx.reply_text, self.llm)
            for f in facts:
                await store.upsert_long_term(self.redis, ctx.object_id, f)  # 含去重合并
            # 5. 遗忘评分 on_tick 批处理（此处不每轮跑，由独立定时任务）
        except Exception as e:
            logger.exception("memory on_turn_complete failed: %s", e)  # 吞异常不阻塞
```

**反思触发条件**：每 `memory_episodic_reflect_interval`（默认 5）次摘要触发一次反思。摘要触发条件：`turn_count % memory_episodic_summarize_threshold == 0`（默认每 12 轮）。

### 4.4 forget_tick（遗忘批处理，独立定时任务）

```python
    async def forget_tick(self) -> None:
        """on_tick 周期任务（apscheduler 或 asyncio 周期循环），遍历所有 object_id"""
        for oid in await store.list_objects(self.redis):
            items = await store.get_all_long_term(self.redis, oid, include_forgotten=False)
            now = int(time.time() * 1000)
            to_forget = [m.id for m in items if should_forget(m, self.cfg, now)]
            if to_forget:
                await store.mark_forgotten(self.redis, oid, to_forget)
            # 物理清理：forgotten=True 且超过保留期的删除
```

```python
async def stage_memory_retrieve(ctx: MessageContext, redis) -> None:
```

**D. `stage_build_messages`**：在 system 与 history 间插入 memory_block。
```python
async def stage_build_messages(ctx: MessageContext) -> list[Message]:
    messages = []
    if ctx.system_prompt:
        # 把 memory_block 拼到 system_prompt 尾部（避免双 system 消息在某些 provider 不支持）
        content = ctx.system_prompt
        if ctx.memory_block:
            content = f"{ctx.system_prompt}\n\n{ctx.memory_block}"
        messages.append(Message(role="system", content=content))
    messages.extend(ctx.history)
    messages.append(Message(role="user", content=ctx.user_text))
    return messages
```

**F. 新增 `stage_memory_write`**：

```python
async def stage_memory_write(ctx: MessageContext, redis) -> None:
    """流结束后异步触发编码/遗忘，失败不阻塞"""
    if not settings.memory_enabled:
        return
    from memory.coordinator import get_memory_coordinator
    coord = await get_memory_coordinator()
    asyncio.create_task(_safe_on_turn(coord, ctx))

async def _safe_on_turn(coord, ctx):
    try:
        await coord.on_turn_complete(ctx)
    except Exception:
        logger.exception("memory write failed")
```

## 10. 风险与降级

| 风险 | 影响 | 降级方案 |
|---|---|---|
| LLM 摘要/事实抽取失败 | 记忆写入丢失 | `_safe_on_turn` 全 try/except 吞异常记日志；失败样本落 `pending`（首版仅日志，M4 加重试） |
| 关键词召回质量低 | 记忆注入不相关 | top-K 兜底；预留 EmbeddingRetriever 接口；recall_result 可为空不影响回复 |
| Redis 不可用 | 全链路失败 | coordinator 各方法 try/except，失败返回空 RecallResult；persona 回退默认卡；stage 内部失败不向上抛 |
| fakeredis 不支持 RediSearch | 测试无法跑向量检索 | 首版纯 Hash+内存关键词，不依赖 FT；embedding 留接口不实现 |
| 人设反推人格漂移 | 人格失控 | 反推走「pending→人工确认」回路，未确认不落正式人设；首版仅记录 |
| 双写（Redis+文件）不一致 | 人设丢失 | 以 Redis 为权威，启动时从文件重建索引；写入顺序 Redis→文件，文件失败仅告警 |
| Long-term 全量 HGETALL 性能 | 对象记忆过多时慢 | `memory_longterm_max_facts=200` 上限，超出触发遗忘淘汰 |
| 多 object_id 并发写 state | mood 竞态 | 同对象串行处理；on_tick 加对象级锁（asyncio.Lock per object_id） |

## 11. 决策落点汇总

| 决策点 | 选择 | 理由 |
|---|---|---|
| 四级记忆 | Core/Working/Episodic/Long-term | Core 承载人设静态+用户核心画像常驻 |
| Working 存储 | 复用 chat_store（`mychat:chat:{oid}`） | 零迁移 |
| 检索首版 | 关键词召回 top-K，零新依赖 | 预留 EmbeddingRetriever |
| memory_block 注入 | 拼进 system_prompt 尾部 | 规避双 system provider 兼容问题 |
| long schema | 以 06 §3 为准补齐 category/emotion | 04 §3.3 字段不完整 |
| 键前缀 | 统一 `mychat:mem:{object_id}:*` | 以 04 为权威，修正 06 简写 |
| 反推触发 | 首版仅记录 pending，算法 M4 | 反推回路复杂，M3 先铺管道 |
| 遗忘定时 | 独立 forget_tick 任务，非每轮 | 避免阻塞对话 |
| PersonaCard.id | prompts 首个 key 或 uuid | 兼容样例 slot |
| conda 环境 | mychat | 已装齐 fastapi/redis/httpx/uvicorn |
