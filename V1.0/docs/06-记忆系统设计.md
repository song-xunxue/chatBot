## 1. 引言

设计聊天对象的**多级记忆系统**，满足 F-C-06（长短期记忆 + 遗忘）、F-C-05（导入记录学习反推人设）、F-C-10（删除/代人反推人格）。本文聚焦记忆**语义与算法**，物理存储见 `04-数据模型` §3.3。

## 2. 设计目标

- **分层**：Core / Working / Episodic / Long-term 四级（2026-06-23 M3 升级，原三级新增 Core 常驻层、Short-term 更名为 Episodic 并含反思），类比人类核心认知→感觉→短时→长时记忆。
- **遗忘**：自主遗忘（评分驱动）+ 手动遗忘，避免上下文无限膨胀、贴近人类「记得重要的、淡忘琐碎的」。
- **反推人格**：把对话历史、删除负反馈、代人正样本转化为对人设的增量修正。
- **可控成本**：记忆检索注入受 token 预算约束。

## 3. 记忆分层架构

| 层 | 类比 | 内容 | 生命周期 | 存储 |
|---|---|---|---|---|
| 核心记忆 Core | 自我/他人核心认知 | 人设静态指令 + 用户核心画像（姓名/关键关系/绝对偏好） | **常驻**，手动维护，不参与召回裁剪 | Redis String(JSON) `mychat:mem:{oid}:core` |
| 工作记忆 Working | 短时工作区 | 最近 N 轮原文 | 滑动窗口（按轮数/token 预算） | Redis List `mychat:chat:{oid}`（复用 chat_store） |
| 情景记忆 Episodic | 近事 + 反思 | 近期对话**摘要**（LLM 总结）+ **反思**（跨对话归纳） | TTL + 活跃度衰减 | Redis ZSet `mychat:mem:{oid}:episodic` + List `mychat:mem:{oid}:reflect` |
| 长期记忆 Long-term | 长时记忆 | 关键事实/偏好/关系/事件 | 持久 + 遗忘评分 | Redis Hash `mychat:mem:{oid}:long` |

每条长期记忆条目结构：
```jsonc
{
  "id": "<mid>",
  "content": "昴君不喜欢吃青椒",
  "category": "preference",        // fact/preference/relationship/event/personality
  "importance": 0.8,                // 0~1，写入时评定
  "emotion": 0.6,                   // 情感强度，影响衰减
  "created_ts": 0, "last_access_ts": 0,
  "access_count": 0,
  "forgotten": false,               // 自主/手动遗忘标记
  "source": "dialog"                // dialog/import/proxy/extract，记忆来源
}
```

## 4. 编码流程（写入）

```
对话结束 → ①工作记忆追加本轮
        → ②周期性摘要：工作记忆溢出时，LLM 总结为短期记忆条目（带 ts）
        → ③固化判定：对短期摘要评分，importance≥阈值 或 反复出现 → 抽取为长期记忆
        → ④去重/合并：与已有长期记忆语义重复则合并并提升 access_count
```

重要度评定（写入时）：由 LLM 按规则评分，综合「是否关于用户核心偏好/关系/重大事件」「是否被强调（用户重复/情感强烈）」「是否人设相关」。强情感/被强调的事件 importance 高、emotion 高。

## 5. 检索流程（提取 → 注入 prompt）

用户消息到达时：
1. **长期召回**：从 `mem:{oid}:long` 中按 关键词匹配（首版）召回 top-K 相关条目；后续可加 embedding 语义召回（向量库可选增强）。
2. **短期补充**：取最近若干条短期摘要。
3. **预算裁剪**：按 token 预算排序保留（importance × recency × relevance）。
4. **注入**：拼入 prompt 的「记忆」段，置于人设之后、工作记忆之前。

> 召回即访问：被召回的长期记忆更新 `last_access_ts` 与 `access_count`（强化保持，呼应 §6）。

## 6. 遗忘机制

### 6.1 自主遗忘（评分驱动，参考人类）

定期（`on_tick`）对每条长期记忆计算**保留分**：

```
retain = w1 * importance
       + w2 * recency_decay(now - last_access_ts)
       + w3 * log1p(access_count)
       + w4 * emotion           // 强情感衰减更慢
```

- `recency_decay`：随时间下降，但每次「被回忆」（召回/被提及）会重置衰减（间隔重复效应）。
- 中性琐碎事件（importance 低、emotion 低、久未提及）→ 保留分跌破阈值 → `forgotten=true`（软遗忘，可恢复，定期物理清理）。
- 强情感/高重要度事件几乎不被遗忘（贴近人脑对情绪事件的保持）。

### 6.2 手动遗忘

- 用户在面板/指令指定遗忘某条记忆、某类（如「忘掉关于 X 的一切」）或某时间段 → 直接置 `forgotten=true`。
- 手动遗忘可设「彻底删除」或「软标记」。

## 7. 人格反推（与记忆/对话联动）

| 来源 | 信号 | 处理 |
|---|---|---|
| 导入历史聊天记录（F-C-05） | 正样本 | LLM 学习总结 → 抽取偏好/习惯/关系事实写入长期记忆 + 反向更新人设（dynamic_state/special_replies） |
| 删除消息 `out_of_character`（F-C-10） | 负样本 | 记录「该表达不符合人格」→ persona_evolve 插件据此约束 LLM 后续表达 |
| 代人聊天用户代答（F-S-03） | 强正样本 | 把用户代答作为「该情境下聊天对象的应有回复」学习，强化风格/语气 |

反推产物分两类落库：**事实类**→长期记忆；**风格/语气类**→人设 `special_replies` / `dynamic_state`。反推采用「增量 + 人工确认」回路，避免人格漂移。

## 8. 记忆与 Prompt 注入结构

```
[system] 人设静态部分（description/personality/scenario/creator_notes）
[memory] 召回的长期记忆条目（top-K）+ 最近短期摘要
[state]  当前 dynamic_state（mood/status/energy）
[working] 最近 N 轮对话原文
[user]   当前用户消息
```

## 9. 与其他模块关系

- **插件**：记忆检索/写入作为管道阶段（记忆阶段），mood_dynamic、persona_evolve 等插件读写记忆。
- **数据层**：物理结构见 `04` §3.3；遗忘标记、访问统计字段在此定义。
- **接口**：面板提供「记忆查看/手动遗忘/导入学习」入口（REST `/memory/*`，后续补充）。
