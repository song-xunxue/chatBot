## 1. 背景与目标

### 1.1 为什么做 V3.0
V2.0 用「QQ 官方机器人」(APPID+AppSecret,腾讯 sanctioned)收发消息。问题:
- 消息**带"机器人"标识**,拟人感打折(V2.0 核心方向是拟人化)。
- **主动消息受月配额限制**(代答/主动发送 `POST /takeover/{oid}/send` 现受限)。
- 富消息能力弱(无戳一戳/撤回/转发/闪照,长文本受限)。

### 1.2 V3.0 目标
换用**标准 QQ 用户身份**(真实 QQ 小号当 bot)收发消息,消息以真人身份发出。技术路径:**OneBot v11 协议端**(NapCat Docker)←反向 WS→ 服务端。

### 1.3 核心约束(已定)
- **不动 V2.0 代码**,新建 `V3.0/`,复用 V2.0 server 核心模块(像 V1.0→V2.0 那样)。
- **V2.0 官方机器人作 fallback**,双栈配置驱动并存,小号被封可降级。
- **专用 QQ 小号**(绝不用主号),热切换设计。
- **先最小验证**(NapCat+小号跑一周评估风控)再全面迁移。

### 1.4 拟人化增益(命中 V2.0 方向)
| 能力 | V2.0 官方机器人 | V3.0 OneBot(用户身份) |
|---|---|---|
| 消息标识 | 带"机器人"标记 | 无标记,真人身份 |
| 主动消息 | 月配额限制 | 不受限 |
| 富消息 | 弱 | 完整(长文本/表情/转发/闪照/戳一戳/撤回) |
| 群聊 | 受限 | 完整 |
| 封号风险 | 无(官方) | **有**(逆向协议,小号是消耗品) |

### 2.1 数据流(入站)
```

    → NapCat → QQ用户
```

## 3. 适配器接口设计(核心)

### 3.1 关键认知:pipeline 是干净的
摸底结论(Explore 报告):
- **pipeline 零 import qq.api_client**,完全平台无关。
- 耦合面 = **4 个出站函数**(`send_c2c_message`/`upload_c2c_file`/`send_c2c_voice`/`send_download`)+ **2 个 ctx 字段**(`qq_msg_id`/`reply_sent`)+ **5 个调用点**(webhook×2 / continuous_send / tts / takeover)。
- `reply_guard.sanitize_reply` 平台无关,V3.0 完全保留。

### 3.2 抽象 AdapterProtocol(消除未来改动面)
V3.0 不再把 `qq.api_client` 直接散落 import,而是抽象统一出站契约,配置驱动选实现:

```python
# V3.0/server/app/adapter/protocol.py(新)
from typing import Protocol, Optional

class PlatformAdapter(Protocol):
    """平台适配器出站契约。official(QQ官方机器人)/ onebot(NapCat)各一实现。"""

    async def send_text(self, oid: str, content: str, *,
                        msg_id: str = "", human_authored: bool = False) -> dict:
        """发文本。oid=用户标识(openid/user_id)。msg_id 被动引用回复。
        human_authored=True 跳过 sanitize_reply(admin 代答)。返 {delivered, mode}。"""

    async def send_voice(self, oid: str, audio_bytes: bytes, *,
                         msg_id: str = "", content: str = "") -> dict:
        """发语音(silk/wav)。返 {delivered, mode}。"""

    async def upload_file(self, oid: str, file_bytes: bytes, file_name: str) -> str:
        """上传文件,返平台文件标识(uri/file_info)。"""

    async def download_attachment(self, url: str) -> bytes:
        """下载消息附件(图片等)用于 vision 解析。"""

    async def init(self) -> None: ...   # 启动(httpx 客户端 / WS 连接)
    async def close(self) -> None: ...  # 关闭
```

### 3.3 两个实现
- `adapter/official.py`:**薄包装**,内部委托 V2.0 现有 `qq/api_client.py`(零重写,只是改调用方从直接 import 改为走 Protocol)。
- `adapter/onebot.py`:**新写**,内部调 OneBot HTTP API。

### 3.4 OneBot v11 适配器实现要点
```python
# V3.0/server/app/adapter/onebot.py(新,~150 行)
# 通过 settings.onebot_http_base 调 NapCat 的 OneBot HTTP API(access_token 鉴权)

async def send_text(self, oid, content, *, msg_id="", human_authored=False):
    text = content if human_authored else sanitize_reply(content)  # 复用守卫
    # OneBot: POST /send_private_msg  {user_id, message, auto_escape}
    resp = await self._http.post(f"{base}/send_private_msg",
        json={"user_id": int(oid), "message": text},
        headers={"Authorization": f"Bearer {token}"})
    return {"delivered": resp.get("status") == "ok", "mode": "onebot_text"}

async def send_voice(self, oid, audio_bytes, *, msg_id="", content=""):
    import base64
    b64 = base64.b64encode(audio_bytes).decode()
    # OneBot CQ 码发语音:[CQ:record,file=base64://...]
    msg = f"[CQ:record,file=base64://{b64}]"
    # (可选 content 同发文本:msg = [纯文本段, 语音段] 消息数组)
    resp = await self._http.post(f"{base}/send_private_msg",
        json={"user_id": int(oid), "message": msg}, headers=...)
    return {"delivered": resp.get("status") == "ok", "mode": "onebot_voice"}

# upload_file → POST /upload_private_file  {user_id, name, file(base64)}
# download_attachment → OneBot 事件已含 CQ 码 url/base64,多数情况无需另下载
```

### 3.5 入站:OneBot 反向 WS 客户端
```python
# V3.0/server/app/onebot/ws_client.py(新,~120 行)
# NapCat 反向 WS 连到本服务(NapCat 配置 reverse_url 指向 server 的 ws://host:port/onebot/ws)
# server 作 WS 服务端,NapCat 主动连上来推事件

@app.websocket("/onebot/ws")   # 或用独立 websockets 库起 ws 服务
async def onebot_ws(ws):
    await ws.accept()
    # 鉴权:NapCat 连接时带 access_token query/header,校验
    async for raw in ws.iter_json():
        if raw.get("post_type") != "message": continue
        if raw.get("message_type") != "private": continue   # 只处理私聊
        user_id = str(raw["user_id"])
        text = raw["raw_message"]   # 含 CQ 码
        message_id = str(raw["message_id"])
        # → 连发防抖合并(复用 webhook._schedule_debounce 逻辑,平台无关)
        # → _flush 构造 MessageContext(object_id=user_id, qq_msg_id=message_id)
        # → pipeline.run_stream(ctx)
```

**入站职责承接 V2.0 webhook 的 4 项**:
| V2.0 webhook 职责 | V3.0 OneBot ws_client |
|---|---|
| Ed25519 验签 | **删**:反向 WS 用 access_token 鉴权 |
| op=13 握手 | **删**:OneBot 无此机制 |
| 连发防抖合并 | **搬**:`_schedule_debounce`/`_flush` 逻辑平台无关,直接搬 |
| 构造 ctx + 调 pipeline + 下发 | **复用**:`object_id` openid→user_id 语义对齐 |

### 3.6 MessageContext 字段(零改/轻改名)
- `object_id`:平台无关,V3.0 存 OneBot `user_id`(int 转 str)。复用。
- `qq_msg_id`:语义"消息 id 用于引用回复"。**保留字段名**(避免动 pipeline),V3.0 存 OneBot `message_id`。或后续重命名 `platform_msg_id`(非必需)。
- `reply_sent`:插件协调契约,平台无关。**保留**。

## 4. NapCat Docker 集成

### 4.1 docker-compose 新增 service
```yaml
# V3.0/docker-compose.yml(在 V2.0 基础上加 napcat;或独立 compose 用外部网络连 V2.0 server)
services:
  napcat:
    image: mlikiowa/napcat-docker:latest   # 社区主流 NapCat Docker 镜像
    container_name: mychat-napcat
    restart: unless-stopped
    environment:
      - ACCOUNT=<QQ小号>          # 待用户提供专用小号
      - WSR_URL=ws://server:8001/onebot/ws   # 反向WS连到 V3.0 server
      - TOKEN=<onebot_access_token>          # 鉴权 token(自定,与 server 配置一致)
    ports:
      - "6099:6099"   # NapCat WebUI(远程扫码登录/重登/查日志)
    volumes:
      - ./napcat/config:/app/napcat/config   # 配置持久化
      - ./napcat/data:/app/.config/qq        # QQ 登录态持久化(避免每次重登)
    networks:
      - chatbot_v2_net   # 与 server 同网络(用容器名 server 互访)
    depends_on:
      - server
```

### 4.2 首次登录流程
1. `docker compose up -d napcat` 启动。
2. 浏览器访问 `http://43.140.219.99:6099`(NapCat WebUI)。
3. 用 QQ 小号扫码登录(首次)。
4. 登录态持久化到 `napcat/data/`,后续重启免扫码(除非异地/风控掉线)。

### 4.3 NapCat 配置要点
- 反向 WS:WSR_URL 指向 server 的 `/onebot/ws`,TOKEN 与 server `onebot_access_token` 一致。
- 启用 OneBot v11 HTTP API(给 server 的 `send_private_msg` 等出站调用)。
- 消息上报:仅 `post_type=message`(收消息),事件推送格式 `action` / `event` 标准 OneBot。

## 6. 专用 QQ 小号热切换设计

### 6.1 小号是消耗品(接受封号)
逆向协议必被风控,V3.0 设计上接受"小号定期换":
- 小号被冻结(数小时~3天):NapCat WebUI 远程人脸/短信/好友辅助解封,或等待。
- 小号被永久封:`docker compose down napcat` → 换新小号 → WebUI 扫码登录新号 → 改 `onebot_self_id` → 重启。

### 6.2 防风控(复用 + 新增)
**复用 V2.0 已有的**(正好兼作防风控):
- `continuous_send` 分段多气泡 + 随机 0.5-1.5s 间隔(像真人连发)。
- `on_before_llm` 思考延迟(收消息后随机 3-5s 才回复,模拟看完再打字)。
- `reply_guard` 出站守卫(不漏错误堆栈,消息自然)。

**V3.0 新增防风控(可选)**:
- 主动消息频率限制(虽然 OneBot 不限配额,但高频主动发仍触发风控,加 token bucket)。
- 夜间降频(深夜减少主动发送频率)。
- 新号"养号期":登录后前几天只被动回复,不主动发,模拟真人逐步活跃。

### 6.3 登录态监控
- NapCat 掉线事件(Q_OFFLINE)→ server 收 OneBot 元事件 → 面板报警 + 日志。
- 心跳:NapCat 每 30s 上报生命周期事件,server 监控超时则告警。
- (可选)面板 System.vue 加"小号状态"卡片(在线/离线/封号疑似)。

## 9. 风险与缓解(汇总)

| 风险 | 等级 | 缓解 |
|---|---|---|
| 小号封号 | **高(无法消除)** | 专用小号+养号+控频+随机延迟+接受消耗品+V2.0 fallback 秒降级 |
| 协议端失效(腾讯更新) | 中 | NapCat 社区活跃,跟踪更新;Lagrange 备选;V2.0 fallback |
| 登录态掉线 | 中 | NapCat WebUI 远程重登;登录态持久化;心跳监控+面板告警 |
| 违反用户协议 | 低(非违法) | V2.0 私聊场景非群发,风险等级低;专用小号隔离主号 |
| 服务器资源(NapCat 占用) | 低 | ~100MB+图形依赖,云服务器可承受;Docker 隔离 |
