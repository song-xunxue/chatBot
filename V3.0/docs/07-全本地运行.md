> 全本地化第二阶段:LLM 走本机 Ollama(qwen3:8b)、TTS 直连本机 GPT-SoVITS,不再依赖云服务器与 frp 隧道。

## 启动与停止顺序

启动按依赖正序:

1. **Ollama**(一键脚本自动处理:在线直接复用,离线设 `OLLAMA_MODELS=D:\ollama\models` 后拉起 serve,轮询 `/api/version` ≤30s;`/api/tags` 查 qwen3:8b 缺失只提示 `ollama pull`,不自动拉)
2. **server + 面板**(同脚本:新窗口起 `local_dev.py`,轮询 `/health` ≤60s)
3. **NapCat**(单独运行;它主动反向连入 server 的 `/ws`,server 起来后再启它即可)
4. **GPT-SoVITS**(按需;不起则语音跳过、文本兜底,链路不断)

停止反序:先停 GPT-SoVITS / NapCat,再关 server 窗口,最后收 Ollama。

Ollama 显存卸载两条路:

- **空闲自动卸载**:Ollama 默认 `keep_alive` 5 分钟,无请求后自动把模型从显存卸下(显存释放,下次首条请求重新加载,多几秒冷启动)
- **手动立即卸载**:`ollama stop qwen3:8b`(要给 GPT-SoVITS 腾显存时用,见下节)

## 显存约束(8GB 上双模型抢显存)

硬件:RTX 4060 笔记本,8GB 显存。qwen3:8b(Q4)常驻约 5.3GB,生成速度 2~4 tok/s;GPT-SoVITS 推理还要 2GB+——**同时跑必抢显存**(OOM 或被挤换页,双双变慢)。

| 方案 | 做法 | 代价 | 适合场景 |
|---|---|---|---|
| a) 换小模型 | `.env` 设 `LOCAL_LLM_MODEL=qwen3:4b` + `ollama pull qwen3:4b`(常驻约 2.6GB,与 SoVITS 共存富余) | 回复质量略降 | 聊天 + 频繁语音,两个都要常驻 |
| b) TTS 按需起 | 聊天时不起 GPT-SoVITS;要发语音前先 `ollama stop qwen3:8b` 释放显存再起 SoVITS,用完先停 SoVITS 再回聊天(或等 keep_alive 5min 自动卸载) | 切换要等模型重载(各十几秒~几十秒) | 多数时间纯文字攒数据、偶尔语音 |
| c) 监控兜底 | `nvidia-smi`(周期刷 `nvidia-smi -l 5`)盯占用,确认 keep_alive 是否已自动卸载、有无野进程占显存 | 无 | 任何时候的排障基本功 |

只聊天/攒数据阶段:8b 常驻、不起 SoVITS 即可,5.3GB 落在 8GB 内富余。

## 思考模式关闭(LOCAL_LLM_DISABLE_THINK)

**为什么必须关**:qwen3 默认思考,Ollama 的 OpenAI 兼容端点(`/v1/chat/completions`)忽略 payload 里的 `think` 字段——思考内容放进独立的 `message.reasoning` 字段(`content` 不含 `<think>` 但 usage 照计)。`max_tokens` 给小时 token 全被 reasoning 吃光 → `content` 为空,这就是此前"max_tokens=40 返回空"的病根。

**机制**(`server/app/llm/local.py`):开关 `LOCAL_LLM_DISABLE_THINK` 默认 true。开时优先走 Ollama 原生 `/api/chat`(base_url 剥 `/v1` 拼接,payload `"think": false` 真正生效,响应归一化成 OpenAI choice 形状);原生端点不可用(ConnectError/HTTPStatusError,如后端是 vLLM)时回退 OpenAI 兼容路径 + 末条 user 消息注入 `" /no_think"` 软关。关时纯 OpenAI 兼容路径;所有路径出口 `_strip_think` 剥 `<think>` 段兜底。

实测(Ollama 0.34.0 / qwen3:8b / 同句「用一句中文说你在本机运行」):

| 方式 | 耗时(s) | prompt_eval | eval_count | content为空 | 回复 |
|---|---|---|---|---|---|
| ① /v1 默认(思考开) | 33.9 | 18 | 222 | 否 | 我是云端AI…(长段跑题) |
| ② /v1 + 注入 /no_think | 51.8 | 22 | 258 | 否 | 我是在云端运行的…(软开关在 Ollama /v1 上无效,token 反而更多) |
| ③ /api/chat + think:false | 17.1 | 24 | 8 | 否 | 我在您的本机上运行。 |
| ④ ① + max_tokens=40 | 2.4 | 18 | 40 | **是** | (空——bug 复现) |
| ⑤ 新代码端到端(走 /api/chat) | 3.1 | - | - | 否 | 我在您的本地计算机上运行。 |

结论:只有原生 `/api/chat` 真正关掉思考(生成 token 222→8);软开关 `/no_think` 在 Ollama /v1 上无效。
