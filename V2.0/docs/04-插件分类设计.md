## 1. 引言

V2.0 决策（用户 2026-06-25 拍板）：**不是所有 AstrBot 插件都当 `.star` 兼容加载**。先识别功能与 V2.0 架构重合的插件 → **融入架构模块**（更内聚、避免钩子冲突与重复实现）；剩余的作 **纯插件**（M6 通过 `.star` 兼容层加载）。本文给出 6 个用户提供的 AstrBot 插件的分类结论、融合落点、子能力拆分与 `.star` 兼容层设计。

V1.0 已有的原生插件（M4 实现）也在本文一并约定 V2.0 的去留。

## 2. 分类原则

| 类别 | 判据 | 处置 |
|---|---|---|
| **融入** | 功能与 V2.0 核心能力（记忆/心情/评分）深度重合，作独立插件会与架构钩子冲突 | 核心逻辑融入架构模块，原插件不留 |
| **部分融入** | 含「V2.0 必需的核心子能力」+「外围增强能力」 | 核心子能力融入；外围能力留作纯插件（.star） |
| **纯插件** | 无状态 / 与架构无耦合 / 增强型能力 | 整体作 .star，M6 兼容层加载 |
| **原生保留** | V1.0 已实现的 V2.0 原生插件 | copy 进 V2.0，按需调整（部分被新机制取代则融入） |

## 4. 融入类详解

### 4.1 angel_memory → 四级记忆实现参考

**为何融入**：其三层认知记忆（Soul 灵魂层 4 维情感槽 / DeepMind 潜意识层 / LLM 主意识层）与 V1.0 四级记忆（Core/Working/Episodic/Long-term）深度重合；其 `on_llm_request priority=40` 钩子会与 V2.0 `memory_retrieve` 重复注入冲突。

**借鉴点（作 M4 记忆融合实现参考）**：
- 三层混合检索（BM25 + 向量 + rerank 降级）→ 强化 V1.0 KeywordRetriever（首版纯关键词，预留 EmbeddingRetriever）
- 加权随机召回 → 避免确定性召回偏见（每次召回相同条目）
- Tanh 橡皮筋灵魂状态 → 心情/情感状态的有界振荡模型（可补强 `03-心情系统` mood 动态）
- 睡眠巩固 → 定期清理/固化长期记忆（强化 V1.0 forgetting retain 评分）

**留外围可选**（不进核心）：research_topic 研究 Agent、多格式知识库解析（PDF/Word/URL）。若 M4 后需要，作独立 .star。

### 4.2 mood_dynamic → 已融入架构（见 docs/03）

V1.0 `mood_dynamic` 插件按 `03-心情系统设计` §9 已**融入架构**（`mood/` 模块 + `pipeline/stage_mood.py`），不再保留为独立插件。此处仅作分类记录，细节见 docs/03。

## 5. 部分融入类详解（子能力拆分）

### 5.1 proactive_chat → 主动聊天/代人聊天模块

**融入核心子能力**（V2.0 必需）：
- 定时/沉默触发主动消息（APScheduler 随机间隔 + 沉默 N 分钟破冰）→ 融入主动聊天模块，原生走 QQ REST 推送（V2.0 服务端一体，本就有推送能力）
- 未回复计数防刷屏 → 融入（避免对 QQ 用户刷屏）
- 免打扰时段 → 融入全局参数

**舍弃/留纯插件**：遥测、通知中心、TTS、分段装饰钩子、独立 React 后台（V2.0 用 Vue dashboard 替代）。

> 与 V1.0 `proactive_msg` 插件（M4.4 已实现：概率+冷却广播）合并收敛为 V2.0 主动聊天模块。

### 5.2 continuous_message → QQ 适配层连发合并

**融入核心子能力**（V2.0 必需，否则硬伤）：
- 私聊防抖合并（首条启动计时器，默认 2s 超时合并）→ 融入 QQ 适配层 / pipeline 入口
- **必要性**：QQ 用户连发 3 条若无合并 = 3 次 LLM 调用 + 3 次记忆读写 + 3 次评分，成本与体验双硬伤；且与 `02-聊天记录Block结构` §7 连发合并策略一致

**留纯插件**：QQ 卡片链接提取、跨平台爬取、合并转发 XML 解析、输入状态感知（这些是 QQ 专属增强，非核心，作 .star）。

### 5.3 outputpro → pipeline 输出阶段

**融入核心子能力**（V2.0 必需）：
- 输出 pipeline 中「分段回复 / 打字延迟 / 输入状态模拟」→ 融入 pipeline 输出阶段
- 与 continuous_message **一入一出**正合：入站合并（continuous）+ 出站拟人化（outputpro）

**留纯插件**：文本清洗、敏感词替换、错字模拟、TTS、文转图、自动撤回、智能引用（增强型，作 .star）。

> 与 V1.0 `reply_enhance` 插件（M4.3：输出合并）功能部分重合，V2.0 收敛为统一的 pipeline 输出阶段。

## 6. 纯插件类

### 6.1 gitee_aiimg（多服务商 AI 文生图）

- 功能：多服务商（含 Gitee AI）AI 文生图/改图/视频，多 Key 轮询，注册 LLM tool `aiimg_generate` 供 tool-loop 调用
- 处置：**纯 .star**，M6 兼容层加载
- 与 V1.0 `image_gen`（M4.3：日配额自主拒绝）关系：V1.0 image_gen 是原生轻量实现；gitee_aiimg 更全（多服务商）。V2.0 保留 V1.0 image_gen 作原生兜底 + 可选装 gitee_aiimg 作增强。两者都注册 tool，tool-loop 按可用性调用

### 6.2 apis（聚合娱乐 API）

- 功能：聚合 160+ 免费娱乐 API（图/视/音/文），关键词正则匹配触发，无 LLM 无状态（依赖独立 Web 聚合器面板端口 4141）
- 处置：**纯 .star**，M6 兼容层加载
- 注意：其独立 Web 聚合器面板（4141）与 V2.0 dashboard 冲突时，仅取其 API 调用逻辑，面板不用

## 8. .star 兼容层设计（M6）

为加载纯插件（gitee_aiimg / apis / outputpro 外围 / continuous_message 外围），V2.0 实现 AstrBot 插件 API 兼容层。

### 8.1 兼容范围

| AstrBot 插件 API | V2.0 映射 |
|---|---|
| `@filter` 装饰器（指令/消息/正则/LLM 请求钩子） | 映射到 V1.0 EventBus 6 钩子（on_message_in/before_llm/after_llm/message_out/tick/delete） |
| `AstrBotContext`（provider/记忆/配置） | 适配为 V2.0 PluginContext（redis/settings/llm provider） |
| `@llm_tool` 注册工具 | 映射到 V2.0 tool-loop 工具注册（供 M5 MCP/工具循环调用） |
| 插件 manifest（`_conf_schema.json`） | 映射到 V2.0 PluginManifest |

### 8.2 加载流程

```
V2.0/Ref/plugins/*.star 目录
  → M6 StarLoader 扫描（importlib 按文件路径，跳过 _ 前缀）
  → 装饰器/Context 适配层包装
  → 注册到 V2.0 PluginManager + EventBus
  → 全局开关 + per-object 配置（沿用 V1.0 键 mychat:plugin:{name}:enabled）
```

### 8.3 限制与降级

- AstrBot 平台事件（群聊/@/频道）在 V2.0 私聊场景无对应 → 适配层对无对应事件静默跳过
- 依赖 AstrBot 特定内部 API 的插件可能不兼容 → 加载失败隔离（沿用 V1.0 异常隔离，不影响其他插件）
- 具体 API 覆盖度待 M6 clone 插件源码后细化（**需梯子访问 GitHub**）
