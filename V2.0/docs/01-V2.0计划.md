# V2.0 开发计划（QQ 机器人 + 拟人化 agent）

> 作者：李文煜  日期：2026-06-25  分支：v2.0（从 dev/v1.1 cb2b784 起）
> 关联：V1.0/（归档的前代 FastAPI+PySide6 实现）、V2.0/Ref/AstrBot/（借鉴参考）、`02-聊天记录Block结构设计`、`03-心情系统设计`、`04-插件分类设计`

## 1. 定位与转向
- **砍掉桌面客户端**：改接 QQ 官方机器人，消息走 IM（无需启动客户端，7×24 持久运行）
- **V2.0 服务端 = QQ 机器人后端**（一体，APPID/Secret 连 QQ 开放平台，部署云）
- 场景：**QQ 私聊 1对1**（官方机器人 C2C）
- 重点：**拟人化 + agent 能力**（联网/MCP/工具循环）+ **评分驱动的反推**

## 2. 关键决策（用户拍板）
| 项 | 决策 |
|---|---|
| IM 平台 | QQ 官方机器人，私聊 1对1，APPID+Secret |
| 开发 | 借鉴 AstrBot + 自研（不 fork 整库，复用其适配层/插件/记忆代码） |
| 复用 V1.0 | 直接复用核心模块（persona/memory/plugins/llm/pipeline/reverse_infer） |

## 3. 架构
```
QQ 用户 ←(QQ开放平台 WS收/REST发, APPID/Secret, 私聊C2C)→ V2.0 服务端(云)
  ├─ QQ 适配层（借鉴 AstrBot QQ官方adapter / botpy）：收消息事件、发消息、@/被动/主动
  ├─ 消息管道（复用 V1.0 pipeline）：persona_inject → memory_retrieve → llm_stream → memory_write
  ├─ 工具循环（借鉴 AstrBot tool-loop）：LLM 调工具 → 执行 → 再调 → 回
  │   ├─ MCP client → 外部 MCP server（Brave搜索/Playwright浏览/Fetch/...）
  │   └─ 自研工具（人设查询/记忆写入/联网兜底）
  ├─ 人设系统（复用 V1.0 persona）：扩字段 + PATCH 深度合并 + reverse_infer 反推
  ├─ 记忆系统（融合）：V1.0 四级（Core/Working/Episodic/Long-term）+ AstrBot 记忆机制
  ├─ 插件系统（复用 V1.0 plugins + AstrBot 兼容层）：装 .star + V1.0 原生插件
  ├─ 评分系统（新）：每条 AI 回复自动 LLM 评分 + 手动覆盖，0-100
  ├─ 代人聊天：Web 面板代答 → QQ REST 发用户
  └─ Web 管理面板（复用 V1.0 dashboard 改）：评分反馈/代答/正反样例/人设健康度
```

## 4. 评分系统设计
- 触发：每条 AI 回复**发用户后**，产生 score(0-100) + score_reason
- 自动评分：另起一次 LLM 调用，prompt「对照该对象人设，给回复打 0-100 分 + 理由」
- 手动覆盖：Web 面板对单条改分
- 存储：消息记录附 score/score_reason
- 驱动反推：score<60 入负样本、score>85 入正样本 → reverse_infer（复用 V1.0）
- 人设健康度：某对象近 N 条均分，面板可视化，低分预警"人设跑偏"

## 5. 四级记忆 × AstrBot 记忆融合
- V1.0 四级：Core（常驻人设/核心画像）/ Working（对话窗口）/ Episodic（摘要反思）/ Long-term（事实+遗忘）
- AstrBot 记忆：对话上下文/知识库/长期记忆机制
- 融合：Working 复用 AstrBot 上下文管理；Episodic/Long-term 用 V1.0 编码管线；Core 用 V1.0 persona；MCP Memory server 可补强

## 6. MCP / 工具循环
- V2.0 内嵌 MCP client，启动连配置的 MCP server（搜索/浏览/fetch）
- tool-loop 借鉴 AstrBot：LLM 决策调工具 → MCP/自研执行 → 结果回填 → 再推理
- 自研工具：get_persona / write_memory / reverse_infer_trigger / 联网兜底

## 7. QQ 官方机器人接入（APPID/Secret 私聊，Webhook 自建适配层）
> **决策修正（2026-06-25）**：QQ 官方 WebSocket 链路 2024 年底已逐步下线、不再维护，强制改 **Webhook**。SDK 路线定为 **自建 FastAPI + pynacl(Ed25519 验签) + httpx(REST)**（不用官方 botpy、不借鉴 AstrBot adapter）。详见 M1 实现方案。
- 接入方式：**Webhook**（HTTP 回调）。回调 URL 填 `https://<域名>/qq/webhook`，**端口硬约束仅 80/443/8080/8443**（当前 8000 不行，M9 部署需 nginx 转发或改端口）
- 鉴权：AppID + **AppSecret** → access_token（Redis 缓存 + 提前刷新）；AppSecret 同时作 Ed25519 验签密钥派生源。**只需 2 凭证**（QQ 文档「Bot Secret」即后台 AppSecret 同一字段；OpenClaw/AstrBot/阿里云佐证，用户后台确认无独立 Bot Secret）
- 签名：Bot Secret 翻倍到 ≥32 字节取前 32 作 seed → 派生确定密钥对；入站事件(op=0)公钥验 `timestamp+body`；回调验证(op=13)私钥签 `event_ts+plain_token` 回包。**已用 QQ 官方 DEMO 金标准验证（M1a 单测 21 项全绿）**
- 私聊 C2C：用户私聊机器人 → C2C_MESSAGE_CREATE 事件(op=0,t=C2C_MESSAGE_CREATE,d.author.user_openid) → pipeline → 回复
- 发消息：`POST /v2/users/{openid}/messages`，`Authorization: QQBot {token}`，被动回复带 msg_id（单聊 60min/4次，2026/01 起）；主动消息无 msg_id（月配额，M8 代人聊天用）
- 审核：开放平台注册机器人 + 资质审核 + 私聊(C2C)权限白名单开通（M1b/M9 验）
- **M1a 本地编码 + 单测已完成（2026-06-25）**；M1b 端到端（真 QQ 私聊收发）留 M9 部署时验证（需域名/HTTPS/白名单）

## 8. 插件分类与兼容（详见 `04-插件分类设计`）
- **分类原则**：非所有 AstrBot 插件都当 .star 加载。与架构重合的→融入；其余→纯插件
- **融入 2**：angel_memory（作四级记忆实现参考，详见 docs/04 §4.1）、mood_dynamic（已在 `03-心情系统` 融入 `mood/` 模块）

- **纯插件 2**：gitee_aiimg（注册 aiimg_generate tool）、apis（关键词触发娱乐 API），作 .star
- **V1.0 原生保留**：reply_enhance/image_gen/tts/sticker_gen/time_aware/proactive_msg 等（persona_evolve 倾向被评分反推取代融入）
