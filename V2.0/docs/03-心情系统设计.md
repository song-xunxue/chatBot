## 1. 引言

V1.0 有 `mood_dynamic` 插件：维护心情值 `mood∈[0,1]`（0.5 中性），按关键词情感 ±step 更新、on_tick 向中性衰减，5 档硬编码 label 注入 system_prompt。但档位**硬编码**、无评分联动、无管理面板。

V2.0 评分系统的核心诉求是「评分不能死板绝对」——人（人设）有情绪起伏，心情好则宽容（给分偏高）、心情差则苛刻（给分偏低）才拟人。本文把 V1.0 心情机制**融入架构**（不保留为独立插件），并新增：**可配置心情种类表**、**离散档位评分补偿**、**颜文字展示**、**Web 管理面板 Mood.vue**。

## 2. 设计目标

| 目标 | 说明 | 对应章节 |
|---|---|---|
| 心情种类可配 | 档位数量/边界/颜文字/补偿值服务端 CRUD，非硬编码 | §3、§6 |
| mood 动态维护 | mood∈[0,1]，情感±step / 时间衰减 / 中性回归 | §4 |
| 评分补偿离散化 | 按当前 mood 所在档位给 score 加 bias，让评分有情绪起伏 | §5 |
| 颜文字展示 | Web 面板 + QQ 回复带颜文字（比 emoji 好看，用户已定） | §7 |
| Web 全可调 | 档位/全局参数/实时监控/试算器全面板可改 | §8 |
| 复用 V1.0 | mood 算法复用 mood_dynamic 思路，融入架构非插件 | §9 |

## 3. 心情种类表（服务端可配置 CRUD）

落点 `server/app/mood/`（V2.0 新增模块）。Redis 键：

| Key | 类型 | 说明 |
|---|---|---|
| `mychat:mood:kinds` | **Sorted Set** | score=`sort`，member=`kind.key`；档位按 sort 排序索引 |
| `mychat:mood:kind:{key}` | **Hash** | 单档位定义（下表字段） |

### 3.1 档位字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `key` | str | 档位标识（如 `happy`），CRUD 主键 |
| `label` | str | 中文显示名（如「开心」） |
| `mood_lo` | float | 档位 mood 下界 [0,1] |
| `mood_hi` | float | 档位 mood 上界 [0,1] |
| `kaomoji` | str | 颜文字（如 `◍˃ᵕ˂◍`） |
| `score_bias` | int | 评分补偿基准（开心+6 / 平静0 / 难过-6） |
| `bias_noise` | float | 补偿噪声幅度（uniform(-noise, noise)） |
| `prompt_hint` | str | 注入 system_prompt 的语气提示（如「语气轻快热情」） |
| `color` | str | 面板展示色（hex，如 `#FFD666`） |
| `sort` | int | 排序权重（小→大，开心在前） |

### 3.2 默认 5 档（复用 V1.0 颜文字，用户已定颜文字优先于 emoji）

| sort | key | label | mood_lo | mood_hi | kaomoji | score_bias | bias_noise | prompt_hint | color |
|---|---|---|---|---|---|---|---|---|---|
| 1 | `happy` | 开心 | 0.70 | 1.00 | `◍˃ᵕ˂◍` | +6 | 3 | 语气轻快热情，多用感叹和颜文字 | `#FFD666` |
| 2 | `pleased` | 愉悦 | 0.55 | 0.70 | `˗ˋˏ♡ˎˊ˗` | +3 | 3 | 语气温和友好，带点小开心 | `#FFB3C7` |
| 3 | `calm` | 平静 | 0.45 | 0.55 | `◌` | 0 | 3 | 语气平稳自然，不特别起伏 | `#C8C8C8` |
| 4 | `down` | 低落 | 0.30 | 0.45 | `˚‧º·(˚˃̣̣̥᷄⌓˂̣̣̥᷅)‧º·˚` | -3 | 3 | 语气低沉，话变少，略带消极 | `#9DB2C8` |
| 5 | `sad` | 难过 | 0.00 | 0.30 | `╥﹏╥` | -6 | 3 | 语气伤心，可能不想说话或欲言又止 | `#7A8FB5` |

> 边界约定：`mood_lo <= mood < mood_hi`（左闭右开），最高档 `mood_hi=1.0` 含端点。默认 5 档边界与 V1.0 `mood_dynamic._label` 阈值（0.7/0.55/0.45/0.3）完全对齐，迁移无歧义。

### 3.3 范围冲突校验（CRUD 时）

新增/编辑档位时校验：任意两条档位的 `[mood_lo, mood_hi)` 区间**不得重叠**，且并集须**覆盖 [0,1]**（不留空档，否则某 mood 值查不到档位）。校验失败 REST 返回 400 + 冲突档位提示。

## 4. mood 动态维护

`mood∈[0,1]`，0.5 中性。Redis 键 `mychat:mood:{oid}`（String，沿用 V1.0）。

### 4.1 更新规则（复用 V1.0 mood_dynamic 算法）

| 触发点 | 规则 | 参数 |
|---|---|---|
| 对话情感（on_after_llm） | 正向词 ↑step / 负向词 ↓step | `step`（默认 0.1） |
| 时间衰减（on_tick） | mood > neutral 向下 decay / < neutral 向上 decay | `decay`（默认 0.05）、`neutral`（默认 0.5） |
| 手动设置（Web 面板） | 管理员直接 SET 某对象 mood 值 | — |

- 情感识别首版用关键词启发式（零依赖，复用 V1.0 正/负向词表），预留 LLM 情感分析接口（M4 记忆融合后可换）。
- 所有更新 `clamp(mood, 0.0, 1.0)`，存时 `round(mood, 3)`。

### 4.2 与 V1.0 的融入差异

V1.0 `mood_dynamic` 是**独立插件**（on_before_llm/on_after_llm/on_tick 钩子）。V2.0 将其逻辑**融入架构**（`server/app/mood/` 服务 + pipeline stage），原因：
- 心情值是评分补偿（§5）与人格反推的**核心状态**，不应作可卸载插件；
- label 查询从硬编码改读种类表（§3），需架构内服务支撑 CRUD。

融入后原 mood_dynamic 插件逻辑迁移为：`mood/service.py`（mood 读写/档位查询）+ `pipeline/stage_mood.py`（注入 prompt_hint + 情感更新）+ `mood/decay.py`（衰减任务，复用 V1.0 TickScheduler）。

## 5. 评分补偿（离散档位）

对接 `02-聊天记录Block结构` 的 message.score 四元组。**仅 ai/proxy 消息**评分时调用：

```python
def compute_mood_bias(mood: float, kinds: list[dict]) -> float:
    """按当前 mood 所在档位算补偿：档位.score_bias + uniform(-noise, noise)"""
    kind = lookup_kind(mood, kinds)        # 找 mood_lo <= mood < mood_hi 的档位
    bias = kind["score_bias"]
    noise = kind["bias_noise"]
    return bias + random.uniform(-noise, noise)   # 噪声让相邻评分不完全可预测，更拟人
```

最终分（写入 message.score 四元组，见 02 §5.1）：

```
mood_at_score = 当前 mood 值（评分时刻读 mychat:mood:{oid}）
mood_bias     = compute_mood_bias(mood_at_score, kinds)
score         = clamp(round(score_base + mood_bias), 0, 100)
```

> 反推阈值判断用 **score**（含补偿），而非 score_base。即「人设心情好时即便回复一般也给高分」是**预期的拟人行为**，不视为人设跑偏。

## 7. 注入与颜文字展示

### 7.1 注入 system_prompt（pipeline stage）

`pipeline/stage_mood.py` 在 before_llm 阶段：
```python
mood = await mood_service.get_mood(redis, oid)
kind = mood_service.lookup_kind(mood, kinds)
ctx.system_prompt += f"\n[当前心情：{kind['label']} {kind['kaomoji']}，{kind['prompt_hint']}]"
ctx.plugin_meta["mood"] = kind["label"]      # 供 QQ 回复与 Web 面板展示
ctx.plugin_meta["mood_kaomoji"] = kind["kaomoji"]
```

### 7.2 颜文字展示

- **QQ 回复**：ai 消息下发时，按当前心情档位在回复末尾附颜文字（概率性，避免每条都加）。具体由 M1 QQ 适配层定。
- **Web 面板**：历史消息气泡 + 实时监控页展示心情档位 label + 颜文字 + color。

## 8. Web 面板设计（Mood.vue 5 Tab）

落点 `dashboard/src/views/Mood.vue`，作**顶级菜单**（与聊天记录/插件/人设平级）。

| Tab | 图标 | 功能 |
|---|---|---|
| 📖 使用说明 | 📖 | 7 节原理文档（心情模型/种类表/动态维护/评分补偿/反推联动/颜文字/FAQ），静态说明 |
| 🎭 档位管理 | 🎭 | 档位 CRUD 表（§3 字段全可编）+ 颜文字实时预览 + 范围冲突校验（§3.3） |
| ⚙️ 全局参数 | ⚙️ | step / decay / neutral / 颜文字附加概率 等全局参数（Redis `mychat:mood:params`） |
| 📊 实时监控 | 📊 | 选 object_id → 显示当前 mood 值 + 所在档位 + 历史曲线（近 N 轮）+ 手动设置 mood 输入框 |
| 🧮 评分试算器 | 🧮 | 输入 score_base + mood → 实时算 mood_bias + score（调 §5 公式），便于调档位参数前预演 |

技术栈沿用 V1.0 dashboard（Vue3 + TS + Naive UI）：表格用 NDataTable、曲线用折线（Naive UI 无内置图表，曲线可用轻量库或 SVG，实现时定）、试算器用 NInputNumber + 计算属性。
