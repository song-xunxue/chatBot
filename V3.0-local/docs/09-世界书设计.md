# 09 · 世界书式记忆（World Book）设计

日期: 2026-10-25（2026-10-27 修订：删除语义对齐实现——面板删除为物理删，软停用仅指自动条目随记忆遗忘）

> 现状：V3.0 记忆是「四级记忆 + 三要素 + 三档衰减」，注入方式偏"全量摘要塞 prompt"。
> 目标：改成 lorebook / 世界书式——**按命中注入、按预算裁剪**，更省上下文、更准，也更适配 DeepSeek 的长上下文与强指令跟随。
> 原则：**旧数据一条不删**，`MEMORY_MODE=legacy|worldbook` 开关可回滚。

---

## 1. 条目模型（Entry）

```jsonc
{
  "id": "uuid",
  "title": "她怕打雷",                  // 人类可读标题（面板显示/检索）
  "content": "打雷的时候她会缩起来，想被人抱着说话。",  // 注入正文（1-3 句，短）
  "keys": ["打雷", "雷声", "下雨"],       // 触发词（命中其一即候选）
  "key_regex": "",                     // 可选正则（进阶用法，优先于 keys 匹配）
  "secondary_keys": [],                // 可选：必须同时命中的键（AND）
  "mode": "trigger",                   // trigger=命中才注入 / always=常驻
  "order": 100,                        // 注入顺序（数字小的靠前）
  "position": "after_persona",         // before_persona | after_persona | before_memories | after_memories | tail
  "probability": 1.0,                  // 命中后仍按概率决定是否注入（避免每次都说）
  "cooldown_minutes": 0,               // 同一会话内冷却
  "token_estimate": 42,                // 估算 token（注入预算用）
  "enabled": true,
  "source": "manual",                  // manual | memory | summary | diary | dream | roleplay
  "source_ref": "",                    // 来源 id（记忆 mid / 日记日期），便于溯源与重建
  "weight": 1.0,                       // 衰减权重（自动条目随三档衰减，手动条目恒 1）
  "stats": { "hits": 0, "last_hit_at": null, "last_injected_at": null },
  "created_at": "2026-10-25T04:00:00+08:00",
  "updated_at": "2026-10-25T04:00:00+08:00"
}
```

**两类来源**
- `manual`：手写设定（她是谁、你们的关系、她的生活习惯、世界观）→ 一般 `mode=always` 或低 order
- 自动：`memory`（四级记忆条目）、`summary`（会话摘要）、`diary`（日记）、`dream`（梦）、`roleplay`（角色扮演抽取）

自动条目的 `weight` 由现有三档衰减维护（避免旧事长期霸占预算），`manual` 不衰减。

## 2. 注入算法（每轮对话前）

```
输入：当前用户消息 U、最近 2 轮对话、会话 oid、预算 BUDGET（默认 2000 token）

1) 收集候选
   a. mode=always 的条目（全部，按 order 排）
   b. trigger 条目：keys 命中 U 或最近 2 轮（大小写/全半角归一化）；key_regex 命中同样候选
   c. 若 a+b 候选中 memory 来源数量 < 3：用现有 retriever 的向量召回补 2-3 条（兜底，不替代手动设定）
2) 过滤
   - enabled=false 跳过
   - cooldown：距 last_injected_at 未过冷却 → 跳过
   - probability：随机 < probability 才保留（always 条目恒保留）
3) 排序
   - 先按 position 分组（before_persona → after_persona → before_memories → after_memories → tail）
   - 组内按 order 升序，其次 weight 降序，其次 last_hit_at 升序（久未命中优先）
4) 预算裁剪
   - 依次累加 token_estimate，超过 BUDGET 即停止（永远先保住 always + 前 3 条 trigger）
   - 裁剪结果记 debug 日志：注入了哪些、裁剪了哪些
5) 渲染
   - 每条渲染成一行 `- {content}`（不加标题，避免模型复读标题）
   - 分组间用空行；整体放在既有 prompt 的对应 position 锚点
6) 记账
   - 命中但未注入的条目：hits 不增（只统计真实注入）
   - 注入的条目：hits += 1，last_injected_at=now，last_hit_at=now（Redis 批量写，失败不阻塞主链路）
```

**为什么不做"全量摘要"**：全量会稀释指令、抬高成本、让旧事霸占注意力；世界书让"相关的事"在当下被提起，这正是"像人"的关键。

## 3. 与现有记忆体系的关系

| 现有能力 | 世界书里的位置 |
| --- | --- |
| 四级记忆（事实/偏好/事件/关系） | 自动生成 `source=memory` 条目，weight 接三档衰减 |
| 三要素（时间/人物/事件） | 条目 content 里保留，keys 由事实里的名词自动生成 |
| 会话摘要 | `source=summary`，mode=trigger，keys 取摘要关键词 |
| 日记 / 梦 | `source=diary|dream`，keys 取梦里出现的意象词，低 order、低概率 |
| 角色扮演抽取 | `source=roleplay` |

写入时机：现有记忆写入路径（encoder / consolidation）成功后，**同步 upsert 一条对应条目**；记忆删除/遗忘时对应**自动条目**置 `enabled=false`（软停用，不物理删，随恢复路径还原）；面板上对手写/单条条目的删除是**物理删**（见 §5）。

## 4. 配置（.env）

```ini
MEMORY_MODE=legacy            # legacy | worldbook（默认 legacy，验收后再切）
WORLDBOOK_BUDGET=2000         # 每轮注入 token 预算
WORLDBOOK_MAX_ENTRIES=12      # 每轮最多注入条数
WORLDBOOK_RECALL_TOPUP=3      # 候选不足时向量兜底的条数
```

## 5. 面板（世界书编辑器）

- 列表：标题 / 来源 / mode / keys / 上次命中 / 命中次数 / 开关
- 过滤：来源、是否常驻、最近命中
- 详情编辑：title、content、keys（标签输入）、mode、order、position、probability、cooldown
- 操作：新建（手写设定）、启用/停用、删除（**物理删单条**；自动条目的「遗忘」是随记忆置 `enabled=false` 软停用，不在此列）、重建自动条目（从记忆/日记重建）
- 顶部统计：条目总数、常驻数、今日注入次数、平均注入 token

---

## 6. 验收标准

1. `MEMORY_MODE=legacy` 时行为与现在**逐字一致**（回归测试锁定）
2. 切到 worldbook 后：固定测试消息 → 注入条目可预测（给出命中清单与 token 数）
3. 预算超限时按规则裁剪，always 条目永不被裁
4. 迁移脚本：现有记忆 → 条目，数量对得上、content 不丢失、可回滚（条目表可清空重建）
5. 面板：条目 CRUD、命中统计可见、切换开关即时生效
6. 全量 pytest 全绿；面板 `npm run build` 通过

## 7. 实施顺序（建议）

1. `memory/worldbook.py`：Entry 模型 + 匹配 + 排序 + 预算裁剪（纯逻辑，先单测）
2. 存储：Redis hash + zset（`mychat:wb:entry:{id}`、`mychat:wb:by_key:{key}`、`mychat:wb:meta`）
3. 接入 prompt 渲染（`persona/renderer.py` 的 position 锚点）
4. 自动条目同步（记忆写入/日记写入处各一行调用）
5. 迁移脚本 `scripts/migrate_worldbook.py`（幂等，可 `--dry-run`）
6. REST + 面板页
7. 验收：legacy 回归 → worldbook 对照 → 切默认

### 8.2 与本设计的偏差

1. **时间字段**：`created_at/updated_at`（ISO 字符串）→ `created_ts/updated_ts`（int Unix 毫秒），与 MemoryItem 全项目口径一致。
2. **stats 结构**：条目内 `stats: {hits, last_hit_at, last_injected_at}` 嵌套对象 → 扁平字段（Redis hash 无嵌套）。
3. **键名**：`mychat:wb:meta` 未实现；统计在 `mychat:wb:stats`（hash，含跨日滚动的 day_injections/day_tokens/avg_tokens 素材）；另增 `mychat:wb:by_ref:{source}:{ref}`（幂等 upsert 索引，免全表扫）。
4. **position 锚点实现**：未改 `persona/renderer.py`（system_prompt 是整块字符串，人设内部插锚会破坏 legacy 逐字一致）；锚点在 `stage_build_messages` 拼装：`before_persona → system_prompt → after_persona → before_memories → [legacy memory_block] → after_memories → tail`。mood hint 在 system_prompt 尾部（stage_mood_inject 时序在检索后），故 after_persona 实际位于 mood hint 之后——语义近似可用。
5. **key_regex 未命中**：回退 keys 匹配（本设计只说「优先于 keys」）；非法正则视为不命中（不炸主链路）。
6. **max_entries 硬顶**：always 数量本身超 max_entries 的极端场景下 always 也截断（否则「每轮最多 N 条」永不成立）；正常场景 always 永不被裁（验收#3 成立）。
7. **预算裁剪**：超预算条目跳过但不 break（更小的后续条仍可进）；保底 = 排序后前 3 条 trigger。
8. **自动同步挂钩位置**：diary/dream/roleplay 不在插件里单独挂钩——它们全走 `coordinator.upsert_facts_batch → _upsert_fact_dedup`，在挂钩处按 `item.source` 映射（`diary` + tags 含 `dream` → dream，否则 diary；roleplay → roleplay；其余 → memory），一处收口零遗漏。
9. **兜底 topup**：复用 `coordinator.retrieve`（BM25+向量 RRF+touch），召回结果转 `topup_` 前缀临时条目参与渲染、不落世界书；召回 mids 写回 `memory_meta.hit_mids` 维持评分 RL 回流与 legacy 同口径。
10. **迁移幂等策略**：先删全部自动来源条目再按当前数据全量重建（重复执行结果一致）；manual 条目永不被动。REST `rebuild` 同逻辑。
11. **自动条目参数**（本设计 §3 只给了方向，落地值）：memory=order100/p1.0/before_memories；summary=150/0.7；diary 与 dream=200/0.5/after_memories；roleplay=120/0.8；core→always/order50；keys=`auto_keys`（中文 2-gram 去停用 + 英数词，上限 8，含记忆 tags）；weight=useful_score。
12. **已有自动条目重复同步**：只刷 content/keys/weight/token_estimate/enabled，面板上调过的 order/position/probability/cooldown/mode 保留。
13. **面板过滤**：来源 + 启用状态（「最近命中」过滤未做，列表显示上次命中时间）；重建走二次确认。
14. **legacy 同步**：MEMORY_MODE=legacy 时记忆写入同样同步世界书条目（切换模式时数据已就绪，同步成本低）。
15. **删除语义**（2026-10-27 修订，对齐实现）：面板/REST 删除单条 = **物理删**（本设计 §5 原文误写「软删」）；「软停用 enabled=false」只发生在记忆遗忘钩子（`mark_forgotten → sync_forget` 全路径）作用于**自动条目**时。
