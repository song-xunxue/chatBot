# 10 · 做梦与日记（dream 插件）

日期: 2026-10-26

> 她是"人"不是助手：每天凌晨 `dream_hour`（默认 4 点）做一次梦——用**昨天**的素材生成一段梦 + 一篇第一人称日记。
> **绝不发 QQ 消息**（插件全链不 import adapter/onebot/takeover 的任何 `send_*`），只落盘 + Redis 索引，
> 精炼版写入事件记忆（source=diary），并按梦的色调给 mood 微小偏移。
> 默认关闭（`default_enabled: false`），面板插件页开关控制。

---

## 1. 功能与流程

```
on_tick(每小时门控) ──> should_dream(到点 + 当日未做)
        │
        └─> run_dream(redis, oid, 目标日=昨天, params)
              ├─ 1.收集素材(四类,全空则直接跳过不调 LLM)
              │    · 目标日长期记忆   memory/store.get_all_long_term 按 created_ts 落在目标日,取前 10 条
              │    · 目标日 mood 曲线 mood/service.get_history_curve 过滤目标日 → [{ts, value}]
              │    · 最近对话 8 条    chat_store.list_messages 取目标日结束时点之前最近 8 条("他:"/"我:")
              │    · 昨日日记摘录     storage.load_entry(目标日-1).diary 前 200 字
              ├─ 2.LLM 生成(resolve_provider("chat", override=llm_provider),不传 max_tokens/temperature)
              │    产出 JSON:{dream 60-200字, diary 300-500字, tone, key_events 1-5条}
              │    解析用 llm/json_extract.extract_json_object(能剥代码围栏);tone 非法归 neutral
              ├─ 3.落盘+索引  storage.save_entry → server/data/diary/<YYYY-MM-DD>.json(原子写)
              │              + ZSET mychat:diary:index + 缓存 mychat:diary:{date}(TTL=keep_days+1天)
              ├─ 4.写事件记忆  MemoryCoordinator.upsert_facts_batch 两条 fact(source=diary,自带去重,
              │              重复补跑不写重):"我做了一个梦:…"(importance 0.6) + "日记(日期):…"(0.55)
              ├─ 5.mood 偏移  tone_offset:positive→+δ / negative→-δ / neutral→0;clamp [0,1],最低 0
              └─ 6.过期清理  storage.cleanup:删 keep_days 前的文件 + 索引 ZREMRANGEBYSCORE + 缓存 DEL
```

**done 键防重**：`mychat:dream:done:{oid}:{yyyymmdd}`（值=目标日串，TTL 3 天）。
只要真正尝试生成就置位（成功或失败都置）——防止 `dream_hour` 小时内每分钟 tick 无限重试烧 LLM；
键按**目标日**判重，所以每天最多做一次，补跑/跨天自动对齐。

**绝不发 QQ**：`plugins/dream/` 三模块（plugin/service/storage）均不 import `adapter`、
`onebot`、`takeover.service` 的任何发送函数；产物只落盘/进记忆/动 mood。

## 2. 参数表（plugin.yaml config_schema）

| 参数 | 类型 | 默认 | 范围/选项 | 说明 |
| --- | --- | --- | --- | --- |
| `dream_hour` | number | 4 | 0–23，步长 1 | 做梦时刻（小时）。该小时内首个 tick 触发，每天最多一次 |
| `dream_mood_delta` | number | 0.05 | 0–0.5，步长 0.01 | 梦对次日心情的偏移量（正梦 +，噩梦 −，中性不动） |
| `keep_days` | number | 90 | 7–365，步长 1 | 日记保留天数，过期文件与索引自动清理 |
| `llm_provider` | string | deepseek | deepseek / glm / siliconflow / local | 做梦用的 LLM 源 |

- `enabled` 不进 config_schema，由 `default_enabled: false` 兜底，面板插件开关控制。
- 代码内同名默认值唯一兜底源：`plugins/dream/service.py` 的 `DEFAULT_PARAMS`
  （REST 手动跑在插件未加载时也用这套）。
- 面板可能存 null——所有取值处都先判 None 再转型（`hour = 4 if hour is None else int(hour)`）。

## 3. 存储布局

| 位置 | 键/文件 | 内容 |
| --- | --- | --- |
| 文件 | `server/data/diary/<YYYY-MM-DD>.json` | entry 全量（ensure_ascii=False + indent=2，先写 .tmp 再 replace 原子写） |
| 索引 | ZSET `mychat:diary:index` | member=日期串，score=YYYYMMDD 整数（支持按范围清理） |
| 缓存 | String `mychat:diary:{date}` | entry JSON，TTL = keep_days*86400 + 86400 |
| 防重 | String `mychat:dream:done:{oid}:{yyyymmdd}` | 值=目标日串，TTL 3 天 |

entry 字段：`date` / `dream` / `diary` / `mood_curve`（目标日 [{ts, value}]）/ `key_events` /
`dream_tone`（positive|negative|neutral）/ `object_id` / `created_ts`（Unix 毫秒）。

## 4. REST 接口（全部 `X-Access-Token` 鉴权，前缀 `/api/v1`）

### GET `/api/v1/diary/list?limit=30`
日记摘要列表（按日期倒序；limit 自动 clamp 1..365）。

```bash
curl -H "X-Access-Token: <token>" "http://<host>:8000/api/v1/diary/list?limit=7"
# {"items": [{"date": "2026-10-25", "tone": "positive", "excerpt": "今天他突然夸我…"}, ...]}
```

### GET `/api/v1/diary/{date}`
单日全量 entry。格式非法（非 `^\d{4}-\d{2}-\d{2}$` 或非真实日期）→ 400；查无 → 404。

```bash
curl -H "X-Access-Token: <token>" "http://<host>:8000/api/v1/diary/2026-10-25"
# {"date": "2026-10-25", "dream": "…", "diary": "…", "mood_curve": [...],
#  "key_events": ["…"], "dream_tone": "positive", "object_id": "1145…", "created_ts": 1798…}
```

### POST `/api/v1/diary/run`
手动跑一次做梦（调试/补做）。body：

```jsonc
{ "date": "2026-10-25", "object_id": "1145077465" }   // 两者都可选
```

- `date` 缺省=今天；非法/未来日期 → 400。
- `object_id` 缺省=最近会话的 oid（做梦不发 QQ，不做数字号过滤）；取不到 → 400
  `"无法确定 object_id,请显式传入"`。
- **不走 done 键门槛，可重复补做**：日记文件覆盖写，事件记忆靠 coordinator 去重不写重
  （mood 偏移会叠加，属预期）。
- `run_dream` 返回 None（无素材/LLM 不可用/解析失败）→ 503 `"生成失败(无素材或LLM不可用)"`。

```bash
curl -X POST -H "X-Access-Token: <token>" -H "Content-Type: application/json" \
     -d '{"date": "2026-10-25"}' "http://<host>:8000/api/v1/diary/run"
```

## 5. 如何手动跑一次

1. **面板**：插件页开启「做梦与日记」（改参数也在该页），日记页（前端另配）点补跑。
2. **REST**（最直接，不依赖插件开关）：
   ```bash
   # 本地直跑
   curl -X POST -H "X-Access-Token: <token>" -d '{}' http://127.0.0.1:8000/api/v1/diary/run
   ```
   成功返回 entry 全量 JSON；同时可在 `server/data/diary/` 看到当天文件、
   面板记忆页看到两条 source=diary 的事件记忆、mood 页看到偏移后的新历史点。
3. **验证定时链路**（不真等到凌晨）：把 `dream_hour` 改成当前小时，等下一个 tick
   （`plugin_tick_interval` 秒级），或临时把 `service._now` monkeypatch 到 `dream_hour` 当口。
   做完后 `redis-cli get mychat:dream:done:{oid}:{yyyymmdd}` 应有值。

## 6. 软失败语义（全链不外抛）

- 素材四类**全空** → 直接跳过（不调 LLM 不落盘，`run_dream` 返 None）。
- provider 不可用 / LLM 调用异常 / JSON 解析失败 / dream 或 diary 为空 → 返 None（不落盘）。
- 落盘失败 → 只 log（索引/缓存不写，保证"有索引必有文件"）。
- 写事件记忆 / mood 偏移失败 → 只 log（日记本体已落盘，不回滚）。
- cleanup 失败 → 只 log。
- 插件 on_tick 任何异常 → `logger.exception` + 返回 CONTINUE，不影响其他插件。
